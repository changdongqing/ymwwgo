## 1. 背景与范围

### 1.1 业务背景：两级编码体系

实际业务中存在两级"编码"，语义不同、载体不同，本文将二者分层定案：

| 层 | 例子 | 挂在谁身上 | 语义 |
|---|---|---|---|
| **类编码** | 国标分类码：GB/T 4754 行业分类 `A0111`、GB/T 2260 行政区划 `110105` 等——标准已把码编好 | **类**（概念本身由标准赋予了编码） | 概念的**注解元数据**：与外部标准/既有数据对接的 join 键、导入映射、报表归集 |
| **个体编码** | 分类编码 + 流水号：`A0111-0001` | **个体**（业务对象实例） | 个体的**业务标识属性**：表单/单据/条码用，人对物的指称 |

类编码采用 W3C SKOS 的标准谓词 **`skos:notation`**（专为"概念的编码/符号"设计）；国标分类表与本体模型的映射：分类标准 ↔ 本体文档、类目 ↔ 类、编码 ↔ skos:notation、名称 ↔ rdfs:label、上下位 ↔ SUBCLASS_OF。

（本仓 01 号文档已把 skos:notation 作为类表单内建字段与校验器谓词白名单成员前置落地——01 §8 差异 #16；本期只补齐"编码成为个体赋码前缀"的下游链路与字符集定案，见 §10。）

### 1.2 06 期在系列中的定位

对应 Protégé 的 `OWLNamedIndividual`：个体按类断型（TYPE_ASSERTION）、挂属性断言（依赖 02 对象属性 / 03 数据属性）、挂注解（04）。个体是"纯组合"——不引入新的建模机制，**但引入本系列唯一的新基础设施：取号器**（§4.1）与**唯一的新表**（`ont_serials`，§3.1）。

对应 Protégé 的 Individuals 标签页（"Individuals by class"）：类→个体分组树 + 选中个体后的类型/属性断言/注解/使用情况四信息区（对照结论见 §1.3，逐项映射见 §9）。

### 1.3 Protégé 对标结论（`protege-editor-owl` 源码）

1. **个体总览** = `OWLIndividualsByTypeViewComponent`：断言类型（具名类）分组树，类节点渲染直接实例计数 `(N)`；另有平铺列表视图。本系统以"左类树 + 右实例列表"左右联动落地，类树节点带直接实例数徽标。
2. **选中个体四信息区**：描述（类型断言 + sameAs/differentFrom）、属性断言（对象/数据两 section）、注解、使用情况——对应本系统 frame 的类型区 / 属性断言区 / 注解区 / usage 接口。
3. **创建面板**（`OWLEntityCreationPanel`）仅 Name 必填 + IRI 实时预览；IRI 可走自动 ID 生成器（`IterativeAutoIDGenerator`：可配前缀/位数/起始，查重重试）——与本文取号器同构，佐证"标识由系统生成、用户只管业务"的产品方向。差异：Protégé 不强制类型，本系统创建必选主类目（赋码依据，§2.4）。
4. **个体弃用**（`DeprecateSelectedEntityAction`）走 `owl:deprecated` 注解而非删除；本系统 01 期已有该内建谓词与渲染缓存，个体支持废弃/恢复近乎零成本（§4.6）。
5. **个体合并**（`MergeEntitiesAction`）、**sameAs/differentFrom 行级编辑**、**负属性断言**均存在——本系统 V1 明确不做（§1.4），作为路线二的远期收益场景保留。

### 1.4 范围声明

**V1 做**：个体 CRUD（声明 + 类型断言 + 编码 + 注解 + 属性断言 61/62）、自动赋码与取号器、编码精确/前缀检索、废弃/恢复、usage 删除保护、类侧 usage 集扩容（+60）、左右联动管理页。

**V1 显式不做**（决策记录，防止范围回潮）：

| # | 不做项 | 理由与出路 |
|---|---|---|
| 1 | sameAs / differentFrom 断言 | 需新增公理号段（63/64），无推理机时价值有限；重复个体纠错暂走"改挂引用（61 断言更新）+ 删旧建新"人工路径——路线二下引用零迁移。V2 候选 |
| 2 | 个体合并向导（对照 `MergeEntitiesAction`） | 依赖 sameAs 或断言迁移策略，随 #1 一并 V2 |
| 3 | 个体批量导入（Excel/外部档案） | V2；V1 单条创建，变更日志已可追溯（07 期 OWL 导入是另一条互操作路径） |
| 4 | 负属性断言（negative object/data property assertion） | 无公理号段预留，需求未出现 |
| 5 | 推理个体（inferred types / 推理 sameAs 行） | 本仓 V1 无推理机（01 号文档决策五） |

## 2. 关键架构决策

### 2.1 决策一：身份与编码分离（路线二，定案）

**个体 IRI 是"哑的稳定标识"，业务编码是可治理的属性断言，二者不混用。**

三个候选路线的完整对比（决策记录，与源同款）：

| | 路线一：编码进 IRI（localName = `A0111-0001`） | 折中：出生编码进 IRI + 编码断言为权威 | **路线二：IRI 独立 + 编码作数据属性断言（采纳）** |
|---|---|---|---|
| 前提 | 编码终身不变 + 满足 NCName | 编码终身基本不变 | 无 |
| 唯一性 | 免费（复用 IRI 查重） | 断言侧仍需服务层校验 | 服务层校验（§2.5） |
| 外部对接 | IRI 即编码 | 需以断言为权威 | 需按值反查（索引见 §3.4） |
| 编码变更时 | **身份手术**：IRI 不可变 → 新建个体 + 旧体废弃 + 迁移全部引用 | 更新断言，IRI 保留旧码（"曾用码"窗口期） | **更新一条断言**，`ont_change_logs` 自动留痕 |
| 纯数字前缀（行政区划码） | localName 首字符非数字（`LOCAL_NAME_PATTERN`），**不合法** | 合法（仅断言） | 合法（仅断言） |

**采纳理由（按重要性排序）**：① 低概率 × 不可逆的事件应移出标识层（路线一下编码重排 = 身份手术，与低概率不相称；路线二下只是带审计的断言更新）；② 纠错频率高于政策性重排（挂错类/录错码/合并重复个体，路线二下均为廉价断言更新）；③ "低概率"要按数据寿命算（国标十年一改版，本体存活 10~15 年撞上概率不低）；④ 决策可逆性单向（路线二 → 路线一有平滑升级路径，反向没有）；⑤ 与 surrogate key / natural key 的经典结论一致。**否决折中**：两个"码"的影子（IRI 码 vs 断言码）需要长期纪律约束。

**落点**：个体 localName **默认由系统生成**（§4.1 取号器，purpose=`ind` 伪前缀 `$ind`，产出如 `i000123`），允许高级模式下手输（走既有 `LOCAL_NAME_PATTERN` + IRI 查重）；**UI 不引导**把编码填进 localName：创建表单 localName 输入框默认折叠于"高级"，编码是独立字段——防止"编码当标识"回潮。

### 2.2 决策二：两个编码的存储载体各归其位

| 编码 | 载体 | 行语义（`ont_axioms`） |
|---|---|---|
| 类编码 | **注解断言**（`AXIOM_ANNOTATION_ASSERTION(100)`） | subject_id=类实体，predicate_iri=`http://www.w3.org/2004/02/skos/core#notation`（内建常量 `PredicateSKOSNotation`，01 号文档 types.go 已含，object_id=NULL），value_text=码，lang=空（编码非语言文本） |
| 个体编码 | **数据属性断言**（`AXIOM_DATA_PROPERTY_ASSERTION(62)`） | subject_id=个体实体，object_id=编码数据属性实体 id，value_text=码（lang=空） |

- **skos:notation 不注册为注解属性实体**（04 号文档 §10 定案）：维持内建常量谓词路径（与 rdfs:label 同轨）；01 号文档"内建谓词行 lang=zh"的规则**不适用**于编码行——编码非语言文本，lang 为空；
- OWL DL 中数据属性断言只能作用于个体，类没有挂数据属性值的语法——类编码挂注解不是风格选择而是语言约束；
- **类表单"编码"字段**：本仓 01 号文档已按独立字段 + 字符集校验落地（非通用注解区，双入口规避，04 号文档 §10 定案）；本期仅将字符集统一为 §3.3 定案（回填 §10）；"曾用码"等扩展元数据按 04 期常规流程创建注解属性实体（如 `ex:formerNotation`）+ 通用注解区承载；
- **编码数据属性实体定案懒创建**：个体赋码需要"编码属性"作为 62 行谓词（object_id 轨），定案为本体级约定 localName=`code` 的数据属性实体（IRI = base_iri + `#code`）——首次 AUTO 赋码（或 MANUAL 未指定）时若不存在，**在同一 EntityChangeSet 内创建**（DECLARATION + 42 值域 xsd:string 行），变更日志同批留痕（源评审修订 #3 定案内化）；高级模式可用 `code_property_id` 指定既有属性。若存在多套编码（国标码/内部码），各建独立数据属性实体，唯一性校验按"属性实体 + 值"分别圈定作用域（§2.5）；
- 个体编码**不走** skos:notation：SKOS notation 是"概念的记号"，本系统固定其为类编码谓词；个体编码是业务属性断言。两载体不混用，防止出现第二套影子编码。

### 2.3 决策三：取号器 = 计数表 + 行锁 + 完整唯一索引，与公理写同事务（本仓事务模板扩展）

不采用 `max(流水号)+1`（并发必撞号），不采用 per 类目 PG sequence（类目数量不可控、迁移困难）。定案（源评审修订 #1 + 实现修订 #1/#2 的最终形态）：

- **计数表 `ont_serials` + 完整唯一索引 `(ontology_id, purpose, prefix)`**：取号路径唯一命中一行由物理约束保证（并发首建后到者在唯一索引撞键 `23505` 并重试收敛到 UPDATE 路径），**不存在双号池窗口**；行不删除、`next_no` 只前进；
- **两段式取号**（`UPDATE … SET next_no = next_no + 1` 未命中 → `INSERT` 首行 → 唯一键冲突重试 UPDATE，`MAX_RETRY=3` 必然收敛）——本仓采用 ent 标准查询路径（Update / Create / catch `23505`），不依赖 PG 方言 upsert/RETURNING（备选实现：`sql/modifier` 原生 `INSERT … ON CONFLICT DO UPDATE … RETURNING` 单语句，语义等价，见 §12 #3）；
- **与公理写同一事务**：本仓 `ChangeApplier.Apply` 是命令式开 Tx，而个体创建需要"先取号（Tx 内）再组装变更再应用"——为此 applier 增加事务模板（本仓架构适配，§12 #2）：

```go
// applier.go 增量（06 期）：Apply 保持既有签名与七步管线不变；新增事务模板供
// "取号等前置动作必须与公理写同事务"的场景——回调在乐观锁检查之后、变更应用之前执行，
// 可在 Tx 内读取数据（主类目 notation 前缀快照）并返回变更列表，框架统一走校验/缓存/版本/日志。
func (a *ChangeApplier) ApplyInTx(ctx context.Context, ontologyID uint32, baseVersion *uint32,
    operation string, fn func(tx *ent.Tx) (changes []AxiomChange, newEntityIDs []uint32, err error),
) (*ApplyResult, error)
```

乐观锁冲突/校验失败整体回滚时 `next_no` 一并回退，**号不损耗**——这是"同事务取号"优于独立事务计数器的地方；SerialAllocator 的取号方法**不自带事务**（只在传入的 Tx 上执行）。

（源项目以 Spring `@Transactional` 声明式事务天然获得"方法级同事务"，本仓命令式事务需要显式模板——`ApplyInTx` 是该差异的等价物，个体创建/改码走它，其余实体保持 `Apply` 不变。）

### 2.4 决策四：主类目规则

多继承下"前缀取自哪个类"必须唯一确定：**创建个体时必选 ≥1 个类型类，第一个即主类目**，取号前缀 = 主类目的 skos:notation。主类目无编码时的行为见 §4.2 第 5 步。

存储落点：`AXIOM_TYPE_ASSERTION(60)` 行的 `sort_order` 承载类型序——**主类目 sort_order=0**，其余类型按提交序 1..n；frame 回读按 sort_order 升序，首位即主类目。UI 语义上"主类目"与"其余类型"显式分开传参（§5），但存储同构，均由服务层落 sort_order。

**主类目变更不改码**（源评审修订 #6 定案）：编码终身不变，update 调整类型/主类目不触发改码；确需换前缀走显式"改码"流程（§4.3）。**类型断言专用 diff**（源实现修订 #7 内化）：类型顺序语义（主类目）必须用全量替换 diff——顺序变化即"删全部旧 60 行 + 按新序增全部"（sort_order 重建），不能复用 `DiffSubjectSideRelations`（它只删缺增新、不重排既有行，主类目变更（次序类提升为主）会失真）。

### 2.5 唯一性与并发总则

- 编码唯一性走服务层校验——同本体 + 同编码属性实体 + value_text 相同即拒绝（`INDIVIDUAL_CODE_DUPLICATE`，409）；**取号号池例外地用完整唯一索引兜底业务键**（§3.1）：整前缀撞号是标识系统不可接受的失败模式，不能只依赖服务纪律（本仓本就有唯一索引惯例——01 号文档已用 partial unique index 兜底 IRI 查重，此处同哲学）；
- 并发双写的极小概率窗口由"本体级乐观锁串行化"兜底：所有写路径经 `ChangeApplier`（`Apply` / `ApplyInTx`）的 baseVersion 比对（行锁 + 比对 + 自增，01 号文档决策四），冲突整体回滚，取号随之回滚（§2.3）；`baseVersion=nil` 跳过校验的内部调用不在并发路径上；
- 取号与业务写**同一事务**（§2.3），本体级乐观锁冲突回滚时号不损耗。

### 2.6 推理影响声明

两级编码均不进入推理：类编码是注解（推理机零语义处理），个体编码是数据属性断言（值相等不产生推理结果，除非显式建 key 公理——V1 不做）。类型断言（60）是唯一有推理语义的 06 期公理（个体继承类层级约束），V1 无推理机，仅做结构校验（§4.5）。编码体系对推理零负担，价值在身份、对接与检索。

## 3. 数据模型（06 期增量——系列唯一 DDL 期）

### 3.1 取号计数表 `ont_serials`（Ent schema + goose `00004_ontology_serial.sql`）

**Ent schema**（`internal/data/ent/schema/ont_serial.go`，type `OntSerial`；平台级表——无 TenantID、无 Policy，参照系列四表）：

```go
func (OntSerial) Mixin() []ent.Mixin {
    return []ent.Mixin{mixin.AutoIncrementId{}, mixin.TimeAt{}, mixin.OperatorID{}}
}
func (OntSerial) Fields() []ent.Field {
    return []ent.Field{
        field.Uint32("ontology_id").Comment("所属本体 id").Optional().Nillable(),
        field.String("purpose").Comment("用途域：ind=个体 localName 伪前缀($ind)；code=业务编码流水").MaxLen(16).NotEmpty().Optional().Nillable(),
        field.String("prefix").Comment("code 时=主类目 skos:notation（如 A0111）；ind 时固定 $ind").MaxLen(128).NotEmpty().Optional().Nillable(),
        field.Uint64("next_no").Comment("下一个流水号；已发放最大号 = next_no - 1；行不删除、只前进（编码/局部名不回收）").Default(1).Optional().Nillable(),
    }
}
func (OntSerial) Indexes() []ent.Index {
    return []ent.Index{
        // 完整唯一索引：取号路径唯一命中一行的数据完整性底线（§2.3/§4.1）。
        // 号池行仅在本体删除时软删，而本体 id 永不复用（identity 不复用），
        // 软删行永不与新行冲突——完整唯一索引与部分索引语义等价且实现最简。
        index.Fields("ontology_id", "purpose", "prefix").Unique().StorageKey("uix_ont_serials_key"),
    }
}
```

**goose 迁移**（`internal/data/migrations/00004_ontology_serial.sql`，与 schema 改动同一 commit——铁律 6 五步；同时承载 `ont_axioms` 的增量索引 §3.4）：

## 4. 服务与流程详细设计（本文核心）

### 4.1 取号器（`internal/data/ontology_serial_repo.go` + `internal/ontology/serial.go`）

```go
// data/ontology_serial_repo.go —— 两段式取号（只在传入 Tx 上执行，不自带事务）：
func (r *OntSerialRepo) NextNo(ctx context.Context, tx *ent.Tx, ontologyID uint32, purpose, prefix string) (uint64, error) {
    // ① UPDATE ont_serials SET next_no = next_no + 1 WHERE ontology_id=? AND purpose=? AND prefix=?
    //    影响行数=1 → 同 Tx 回读 next_no，本次发放号 = next_no - 1（行锁持至提交，回读稳定）
    // ② 影响行数=0（该前缀首次使用）→ INSERT 号池行（next_no=2，首号=1）
    //    并发首建撞 uix_ont_serials_key（23505）→ 重试 ① 路径（MAX_RETRY=3，必然收敛）
    //    重试耗尽 → INDIVIDUAL_SERIAL_CONFLICT
}

// ontology/serial.go —— 格式化与字符集（纯函数，可单测）：
func FormatCode(prefix string, seq uint64) string   // 前缀 + "-" + LPAD(流水, 4, '0')，超 9999 自然扩位
func FormatLocalName(seq uint64) string             // "i" + LPAD(流水, 6, '0')，同款自然扩位
var codeCharsetPattern = regexp.MustCompile(`^[A-Za-z0-9][A-Za-z0-9._-]*$`)
func ValidateCodeCharset(code string) error         // → INDIVIDUAL_CODE_PREFIX_INVALID
```

语义定案：① 唯一索引兜底 + 行锁串行（§2.3，无双号池窗口）；② **回滚不跳号**（取号与业务写同事务，§2.3 的 `ApplyInTx`）；③ **流水号不承诺连续**（个体删除号不回收、手输编码占用、号段预留都造成空洞——业务编码是标识不是序位）；④ 前缀快照：取号事务内读取主类目 notation，编码前缀以此刻值为准——类编码并发变更由本体乐观锁串行化，不存在半新半旧。

### 4.2 创建个体事务管线（走 `ApplyInTx`，回调整体内完成取号与组装）

```
1. 本体存在且启用校验
2. 主类目校验：main_class_id 非空（否则 INDIVIDUAL_MAIN_CLASS_REQUIRED）；
   type_ids（主类目 + 其余类型）经 ValidateRefEntities(…, CLASS, ENTITY_TYPE_MISMATCH)
3. localName：默认自动生成（purpose='ind', prefix='$ind' 取号 → FormatLocalName）；
   用户手输（高级模式）→ ValidateLocalName + IRI 查重（ENTITY_IRI_DUPLICATE）
4. 进入 ApplyInTx 回调（以下全部在同一 Tx 内）：
   a. 编码属性解析（懒创建，§2.2）：按 localName='code' 解析本本体数据属性实体；
      不存在且本次需落编码 → 计入同一 ChangeSet（实体行 + DECLARATION(10) + 42 值域 xsd:string 行）；
      高级模式 code_property_id 显式指定时校验（存在、同本体、DATA_PROPERTY 类型 → DATA_PROPERTY_TARGET_INVALID）
   b. 编码来源（code_source）：
      AUTO   → 读主类目 100 注解行（predicate_iri=PredicateSKOSNotation）：无编码 → INDIVIDUAL_CODE_SOURCE_INVALID；
               有编码 → 前缀字符集校验（§3.3）→ purpose='code' 取号 → code = FormatCode(前缀, 流水)
      MANUAL → 用户手输 code（空 → INDIVIDUAL_CODE_REQUIRED）→ 字符集校验
   c. 编码唯一性校验（同本体+同编码属性+值 → INDIVIDUAL_CODE_DUPLICATE）
   d. 组装 EntityChangeSet（operation="CREATE_INDIVIDUAL"）：
      DECLARATION + TYPE_ASSERTION×N（主类目 sort_order=0，其余按提交序）+ DATA_PROPERTY_ASSERTION(编码)
      + ANNOTATION_ASSERTION(label/comment/deprecated 可选) + 自定义注解（04 双轨）
      [+ 懒创建的声明/42 行] → 框架统一执行（乐观锁 → 公理增删 → 注解缓存同步 → 校验 → version+1 → 日志）
```

### 4.3 更新：类型 / 编码 / 属性断言三区 diff（frame 全量提交）

| 区 | diff 规则 |
|---|---|
| 类型区 | **专用全量替换 diff**（§2.4：顺序变化即删全部旧 60 行 + 按新序增全部，sort_order 重建）；主类目变更**不触发改码** |
| 编码区 | 编码字段变化 → diff 出"删旧 62 行 + 增新行"（纠错/重排，同一事务、同一乐观锁、变更日志留痕）；UI 编辑时编码区默认只读 + 显式「改码」动作开启编辑（切 MANUAL 输入新码） |
| 属性断言区 | `object_assertions`（61）按 `(predicate_iri, target_id)` 键、`data_assertions`（62）按 `(property_id, value, lang)` 键全量替换 diff（**编码 62 行归编码区管，不参与本区比对**）；前置校验：61 谓词须命中本本体已声明对象属性（`PROPERTY_TARGET_INVALID`）+ 两端为已声明个体（`INDIVIDUAL_TARGET_INVALID`）、62 属性须为已声明数据属性 + 词法按属性值域校验（校验器统一兜底） |
| 注解区 | `DiffAnnotations`（内建）+ `DiffCustomAnnotations`（04），全量替换语义 |

**主类目变更不改码**：update 调整主类目/类型不触发改码——"编码终身不变"与 §2.1 决策一致；主类目变化时 UI 提示"已赋编码不变，如需换前缀请使用改码"。**类编码重排**（国标改版）：只改类的 notation 注解行，**不级联变更任何已有个体**——旧个体保留出生前缀，仅新个体用新前缀取号；新旧码关系按 04 期常规流程建注解属性承载，V1 依赖变更日志追溯。**个体编码重排**：批量走"改码"逐个更新断言，IRI 与类型断言不动，引用零迁移——路线二的核心收益场景。

### 4.4 删除与 usage 保护

**个体删除**（02 号文档 §2.6 定稿语义）：

- 个体"被引用" = `AXIOM_OBJECT_PROPERTY_ASSERTION(61)` 的 object_id 命中（作为关系宾语）；主语侧断言（60/61/62/100）属于个体自身 frame，不计入被引用；

**类删除保护（本期扩容 + 双态拒绝）**：

- `ClassUsageAxiomTypes` 由 `{20,21,22,31,32,41}` 扩为 `{20,21,22,31,32,41,60}`——01 号文档预埋的 06 期执行点兑现；前端类页 usage 弹窗 refTypeName 补 `60 个体断型` 标签；
- **有实例断言的类**：`force=false` 拒绝并列出实例个体清单；**`force=true` 亦拒绝**，提示"该类存在 N 个实例个体，请先删除或改挂他类"——偏离 02/03 期"force=true 级联"惯例，理由：个体必须 ≥1 类型（创建不变量，§2.4），级联删 60 行产出"无型个体"破坏不变量，级联删个体则把单实体删除放大为批量删除，均不可接受；

- 无实例的类删除不受本期影响。

**对象属性 usage 集**：02 号文档 §4.3 预告的"06 期追加 61 谓词行"兑现——对象属性 usage 反查含 61 行（predicate_iri 命中属性 IRI，引用方为主语个体）；数据属性 usage 集含 62 行（object_id=属性实体，03 号文档 §4.3 已预告）。

### 6.1 页面骨架（左右联动）

- 顶部：`OntologySwitcher` + 搜索区（keyword + 编码输入 + 精确/前缀切换 + "含子类实例"开关 + 废弃筛选）+ 新增按钮（`AccessControl`）；

### 6.2 列表列

编码（mono）、显示名（渲染缓存，deprecated 删除线灰显）、主类目（聚合列返回的 brief）、局部名、类型数、状态（废弃 tag）、更新时间、操作列（编辑 / 废弃|恢复 / 删除）。

### 6.3 创建 Drawer（字段顺序即录入动线）

1. **主类目**（`TreeSelect`，必选，`INDIVIDUAL_MAIN_CLASS_REQUIRED` 前端前置校验；数据源 = 全量类树按需加载）；
2. **预计编码**（AUTO 模式）：主类目选定后实时调 `code-preview`，展示"预计编码：`A0111-0001`（并发下实际号以提交为准）"——预览不加锁，实际号提交时才定（§5）；
3. **其余类型**（`TreeSelect` multiple，可空）；
4. **编码模式**（`Radio.Group` AUTO/MANUAL）：MANUAL 切出编码输入框，明示"手输编码将跳过取号器"；
5. 显示名 / 备注 / 废弃开关；
6. **自定义注解区**：`AnnotationListEditor` 零成本复用（04 期共享组件）；
7. **"高级"折叠区**：localName 手输（防"编码当标识"回潮，§2.1 落点）+ 编码属性 `code_property_id` 指定（`Select`，数据源 = 数据属性简表）。

### 6.4 编辑 Drawer（frame 全量提交）

- 顶部实体横幅：显示名 + 完整 IRI（对照 Protégé `SelectedEntityCardView`）；
- **类型区**：主类目（可改，提示"改主类目不影响已赋编码"）+ 其余类型；服务层专用全量替换 diff（§2.4）；
- **编码区**：默认只读展示当前编码；「改码」按钮显式开启编辑（切 MANUAL 输入新码）→ 提交后服务层 diff 62 删旧增新（§4.3）；
- **属性断言区**（61/62 行编辑，对照 Protégé 属性断言视图两 section，`Form.List`）：
  - 对象属性断言：对象属性下拉（02 期树数据扁平化）+ 目标个体远程搜索（List 接口 `keyword`/`code` 过滤）；
  - 数据属性断言：数据属性下拉（03 期树数据）+ 值输入，**按该属性 42 值域渲染控件与词法预提示**（`lexical.go` 只读复用——05 号文档 §4.6 预留点兑现：值域为数值族给 `InputNumber`、日期给 `DatePicker`、pattern 给正则即时提示；前端不引后端逻辑，仅按值域元数据切控件）；
- 注解区：同创建；
- 提交 = 全量 + `base_version`，服务层逐区 diff（§4.3）；提交成功后 frame/列表/计数徽标 invalidate 重载。

### 6.5 删除与废弃交互

- 删除前先取 frame（拿 `base_version`，系列惯例）+ `usage` 引用清单；`ENTITY_IN_USE` 时展示引用方个体；确认文案含编码："编码 `A0111-0001` 将随个体删除，编号不回收"；
- 废弃/恢复为列表行内按钮（§4.6），无需二次确认页。所有 catch `console.error` 原始错误（铁律 1）。

### 6.6 hooks（`api/hooks/ontologyIndividual.ts`）

`useListIndividuals` / `useIndividualFrame` / `useIndividualCodePreview`（queryKey `['individualCodePreview', ontologyId, mainClassId]`）/ `useIndividualsCountByClass` / `useIndividualUsage` / `useCreateIndividual`（**扁平 body**）/ `useUpdateIndividual` / `useDeleteIndividual`。

## 7. 异常与边界场景清单

| # | 场景 | 行为 |
|---|---|---|
| 1 | 主类目无 skos:notation | 自动模式拒绝（`INDIVIDUAL_CODE_SOURCE_INVALID`）；UI 引导切换手输模式或重选主类目 |
| 2 | 类编码含非法前缀字符 | `INDIVIDUAL_CODE_PREFIX_INVALID`；类编辑表单对 notation 同步做字符集校验（§3.3 定案字符集，入库前拦截） |
| 3 | 并发创建同前缀个体 | 两段式取号行锁排队，各得各号；后提交者若版本冲突整体回滚（号不损耗） |
| 4 | 编码重复（含手输撞自动号、手输撞手输） | 服务层校验拒绝（`INDIVIDUAL_CODE_DUPLICATE`）；并发双写窗口由本体乐观锁 + 号池唯一索引兜底（§2.5） |
| 5 | 个体删除 | usage 保护（61 宾语命中）：force=false 拒绝并列清单；force=true 级联删"以我为宾语"的 61 行（02 号文档定稿）；**号不回收** |
| 6 | 主类目被删除 | `ClassUsageAxiomTypes` 已扩 +60（§4.4）：force=false/true 均拒绝并列出实例个体清单（个体必须有型） |
| 7 | 多继承 | 前缀仅取主类目（sort_order=0）；补挂第二类型不影响已赋编码 |
| 8 | 手输编码覆盖自动赋码 | 允许（MANUAL 模式），同样做唯一性 + 字符集校验；UI 明示"手输编码将跳过取号器" |
| 9 | 取号行首建并发 | 唯一索引 + 两段式（UPDATE→INSERT→23505 重试）原子收敛（§4.1）；重试耗尽 → `INDIVIDUAL_SERIAL_CONFLICT` |
| 10 | 直改库造成 serial 漂移 | 与缓存漂移同款态度：仅服务层写路径改号，直改库属运维操作，下次取号以库中 next_no 为准（唯一索引保证不会出现双号池行） |
| 11 | 主类目变更 | 编码终身不变、不触发改码（§4.3）；UI 提示；换前缀走显式改码 |
| 12 | 编码属性 `code` 不存在 | AUTO 首次赋码时同事务懒创建（DECLARATION + 42 xsd:string，§2.2）；变更日志留痕 |
| 13 | 个体废弃 | owl:deprecated 标记（§4.6）；列表灰显可筛；编码与断言保留 |
| 14 | 本体删除 | 号池行级联软删（§3.1）；重建同名本体 = 全新编号空间 |
| 15 | code-preview 与实际取号偏差 | 预览不加锁，并发下实际号可能 +N；文案固定"预计"（§5） |
| 16 | 61 断言目标/谓词非法（手写请求） | 谓词未声明 → `PROPERTY_TARGET_INVALID`（02 期码）；目标非个体 → `INDIVIDUAL_TARGET_INVALID`；校验器双拦 |
| 17 | 62 断言词形不满足值域（含派生 facet） | 校验器拒绝（03/05 号文档既有链），个体编辑器前端另有词法预提示（§6.4） |
| 18 | object_assertions / data_assertions 空提交 | **全量替换语义**：空/nil = 清空断言区（§12 #5；与 04 annotations 同款，编码行不受影响） |
| 19 | 乐观锁冲突 / 并发创建同名（自动 localName） | 冲突 409 引导刷新；自动 localName 由取号器串行发放，不重号 |
| 20 | 缓存漂移 / 本体停用 / 误包 `{ data }` | 同系列既有行为 |

## 8. 验收标准与测试要点

**域内核单测**（`internal/ontology` 纯函数，`go test`；取号 SQL 与并发行为无内存库可测，转端到端——§12 #6）：

- `serial.go`：FormatCode/FormatLocalName（LPAD 补零、9999/999999 自然扩位）、编码字符集正/反例（纯数字前缀合法、`$`/空格/首字符点拒绝）；
- 类型断言专用 diff：全量替换（顺序变化删全部增全部、sort_order 重建）、主类目提升场景；
- 编码 diff：删旧增新两行、等值无操作（行 id 不变）；
- 断言区 diff：61 按 (predicate_iri, target_id)、62 按 (property_id, value, lang) 键比对（含同属性多值、lang 区分）；编码 62 行不参与断言区比对；
- 校验器：60 规则（object 非 CLASS 拒绝、个体无 60 行防御拒绝）、61 规则（谓词未声明拒绝、两端非个体拒绝）、62 存量回归。

**端到端验收**（本地 dev 栈：容器栈 PG + `air` 起 admin + `pnpm dev` react；验证前端先确认请求到达后端）：

1. 类 A（notation `A0111`）→ 个体创建（AUTO）→ 编码 `A0111-0001`；再建 → `A0111-0002`；**直查库确认 62 行 object_id=code 属性实体、懒创建的 DECLARATION + 42 行同批落库**；
2. **并发取号**（脚本并发 10 个创建请求）→ 编码无重号、无跳号异常；
3. **版本冲突回滚号不损耗**：两标签页并发，后提交者 409 → 其占用的号回滚 → 下一次创建号连续；
4. 主类目变更 → 编码不变（UI 提示）；显式改码 → 62 行 diff 两条、变更日志留痕；
5. 类编码重排（A 的 notation 改 `B0222`）→ 旧个体编码不动、新个体用新前缀；
6. 编码唯一性拒绝（手输撞码 → `INDIVIDUAL_CODE_DUPLICATE`）；非法字符集拒绝；
7. 编码精确/前缀检索（`A0111-` 前缀走 `idx_ont_axioms_type_value`，EXPLAIN 验证走索引）；
8. 61 断言：个体甲 locatedIn 个体乙 → 甲乙 frame 各自回显（主语侧/宾语侧）；删除乙（force=false）→ 拒绝并列出甲；force=true → 甲的断言区该行消失；
9. 删除个体 → 号不回收（下一创建续发）；废弃/恢复 → 列表灰显与筛选；
10. **类删除保护**：删除有实例的类 A → force=false/true 均拒绝并列出实例清单；删除无实例的类 → 不受影响；
11. `count-by-class` 徽标正确；`code-preview` 显示"预计"文案；
12. 菜单 117 落库、平台管理员可见（老库「菜单同步」）。

**门禁**：`make build`；`go test ./internal/ontology/...` 全绿（01~05 期回归）；`make db-drift-check`（**本期有 DDL，schema 与 00004 迁移一致性必查**）；`pnpm run typecheck` 全绿。

## 13. 实现修订记录（2026-10-22，实现期偏差记档）

实现过程中发现并就地更正的设计缺陷与代码级偏差，全部已内化进代码与上文对应章节：

| # | 主题 | 设计原文 | 实现定案 | 理由 |
|---|---|---|---|---|
| 1 | **ApplyInTx 签名适配**（§2.3） | `fn func(tx *ent.Tx) (changes []AxiomChange, newEntityIDs []uint32, err error)` | 回调收 **AxiomTx 接口**（域内核依赖纪律：不触 `*ent.Tx` 具体类型），返回**组装完成的 EntityChangeSet**（含懒创建实体的 NewEntities 草稿，框架统一落库并解析 ref）；`operatorID` 显式入参 | 本仓域内核以 `AxiomStore`/`AxiomTx` 接口隔离 ent；"返回 newEntityIDs"与"框架落库新实体"矛盾——草稿 ref 机制（SubjectNewEntityRef）才是本仓新实体桥接的既有形态；取号经 `tx.(ontology.SerialTx)` 接口断言取用（小接口注入，不扩 AxiomTx 面） |
| 2 | **创建管线的取号边界**（§4.2 步骤 3/4） | 步骤 3"localName 自动生成（取号）"写在进入 ApplyInTx 回调**之前** | ind 与 code 两次取号**全部在回调内**执行（步骤 3 只决定模式），否则取号游离于事务外、回滚跳号 | §2.3 自身"取号与业务写同一事务"的要求优先于步骤编号顺序；文档步骤 3/4 的边界表述失准，已按实现语义读 |
| 3 | **懒创建实体声明 ref 改写** | 未提及 | `CreateEntityDraft` 硬编码 `SubjectNewEntityRef=1`（NewEntities[0] 惯例）；懒创建的编码属性草稿挂在个体之后，其声明与 42 行的 ref **必须改写为实际下标**，否则声明错绑到个体（校验器"声明数量应为 1"拦截，端到端实测暴露） | 草稿 ref 机制的零值安全约定依赖"草稿固定 index 0"，多草稿场景是 06 期首次引入的新形态 |
