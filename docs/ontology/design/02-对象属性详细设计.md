## 1. 背景与范围

### 1.1 业务背景与产品定位

01 期交付"概念的分类词汇表"（类层级）；02 期交付"**关系词汇表**"——把业务中反复出现的实体间关系（如"隶属于""位于""生产""上级组织"）定义为一等公民的建模资产。对象属性与 03 期数据属性的分工（Protégé 的经典二分）：

| | 对象属性（OWLObjectProperty，02 期） | 数据属性（OWLDataProperty，03 期） |
|---|---|---|
| 连接什么 | 个体 → **个体**（如"张三 locatedIn 华东区"） | 个体 → **字面量**（如"张三 age 42"，06 期个体编码即走此路） |
| 值域 | 类（个体的类型约束） | 数据类型（05 期） |
| 特征 | 七种全支持（函数性/逆函数性/传递性/对称性/反对称性/自反性/反自反性） | 仅函数性 |

产品价值按消费方排序：① 06 期个体断言的谓词来源（没有对象属性，个体之间无法建立关系）；② 类表达式约束的谓词来源（01 期范围外的 `some/all` 表达式，02 期后开放）；③ 关系词汇表本身的管理与复用（域/值域约束让"关系连错类型"在建模期即被拦截）。

### 1.2 02 期在系列中的定位

01 号文档 §1.1 的开发顺序判定：属性族是"类管线的增量实例化"——实体注册、公理事务、编译校验、树/列表 UI 全部复用阶段0 沉淀。源项目 02 期要做的两件基础设施重构（层级算法上移泛化、frame diff 下沉），在本仓**已前置消化在 01 号文档的设计里**（`internal/ontology/hierarchy.go` 生而参数化、`changeset.go` 本就是公共 diff 组件，见 §2.3/§2.4），02 期只剩"以新参数值实例化 + 新增链 diff"。

另有一项对 06 期的**契约回收**：源 06 期文档悬置的"对象属性断言行语义（61）与个体 usage 反查集"，本文 §2.6 定稿（与源同款）。

### 1.4 范围声明

**V1 范围内（In Scope）：**

| 能力 | Protégé 对应 |
|---|---|
| 创建/删除对象属性（局部名、显示名、注释、废弃标记，一次事务） | `CreateNewObjectPropertyAction` + frame 编辑 |
| 属性层级树（多父、虚拟根 owl:topObjectProperty；全量树，无 nav 剪枝——属性数量级远小于类） | `OWLObjectPropertyHierarchyViewComponent`（Asserted 层级） |
| 子属性关系（多父） | `SubProperty Of` frame 节 |
| 定义域 / 值域（V1 仅命名类，多值） | `Domains And Ranges` 视图 |
| 七种特征（复选框组，随 frame 一次提交） | `Characteristics` 视图 |
| 逆属性（多值，成对存储） | `Inverse Of` frame 节 |
| 不相交属性（多值）、等价属性（V1 单值，对齐 01 期类建模收敛） | `Disjoint With` / `Equivalent To` frame 节 |
| 属性链（有序属性序列 ⊑ 超属性） | `Property Chains` frame 节 |
| 分页列表 + 搜索 + 特征标签列 | `Findable<OWLObjectProperty>` |
| Usage 反查 + 删除保护（force 级联） | `OWLObjectPropertyUsageViewComponent` + `OWLEntityDeleter` |
| 层级环禁止（含自环） | Protégé 树同理禁止 |

**V1 范围外（Out of Scope，写明去向）：**

- 属性上挂复杂类表达式域/值域（`some/all/not/and/or`）→ 与 01 期类表达式同批开放（`ont_axioms.value_text` 承载表达式 JSON 的思路同理预留）；
- 推理层级（Inferred property hierarchy）→ 接入 reasoner 后独立迭代（本仓无推理机，见 01 号文档决策五）；
- 属性 IRI 重命名、批量导入、跨本体属性引用（`owl:imports`）→ 后续迭代（07 期及以后）；
- 特征组合的一致性检查（如 symmetric+asymmetric）→ 不做，见 §2.7。

## 2. 关键架构决策

### 2.1 决策一：零 DDL 增量——属性实体与公理完全复用既有两表

`ont_entities.entity_type = 20 (OBJECT_PROPERTY)`（01 号文档 proto 枚举已备），公理落 `ont_axioms`（`predicate_iri` / `value_text` / `sort_order` 列均为阶段0 预留位）。**本期不需要任何表结构变更与 goose 迁移**，落库侧唯一产出是菜单种子（`default_data.go`，§3.3）。这是 01 号文档"号段预留六项"决策的直接兑现，验证该架构的扩展性正是本期的隐式目标。

### 2.2 决策二：公理类型落位 30~37，特征采用"泛型类型 + 谓词 IRI"

**号段预算**：proto 枚举 `OntologyAxiomType` 为 02 期预留 30~39 共 10 槽。需要承载的语义：子属性、定义域、值域、逆属性、等价、不相交、属性链 = 7 个，剩 3 槽，而特征有 7 种——**每特征一个枚举值的方案放不下**，且 03 期数据属性特征（Functional）无法复用。定案（与源一致）：

```proto
// ontology_class.proto 所在包新增/启用（01 号文档 §3.7 枚举的预留注释逐条转正）：
AXIOM_SUB_OBJECT_PROPERTY_OF          = 30;  // 子对象属性：subject=子属性, object_id=父属性
AXIOM_OBJECT_PROPERTY_DOMAIN          = 31;  // 定义域：subject=属性, object_id=类（多行=多定义域，OWL 交集语义）
AXIOM_OBJECT_PROPERTY_RANGE           = 32;  // 值域：同上
AXIOM_OBJECT_PROPERTY_CHARACTERISTIC  = 33;  // 特征（泛型）：subject=属性, predicate_iri=特征 IRI，每特征一行
AXIOM_INVERSE_OF                      = 34;  // 逆属性：成对 (P,Q)+(Q,P) 各一行
AXIOM_EQUIVALENT_OBJECT_PROPERTIES    = 35;  // 等价：成对（frame 单值暴露，存储为成对）
AXIOM_DISJOINT_OBJECT_PROPERTIES      = 36;  // 不相交：成对
AXIOM_SUB_PROPERTY_CHAIN_OF           = 37;  // 属性链：subject=超属性, value_text=链成员实体 id 的 JSON 数组（保序）
// 38~39 继续预留
```

**特征存储对比（源决策记录，本仓采纳同款）：**

| | 方案 A：每特征一个枚举值 | **方案 B：一型 + predicate_iri（采纳）** |
|---|---|---|
| 号段占用 | 7 槽（放不下） | 1 槽 |
| 谓词列语义 | 空置 | 复用既有 `predicate_iri`（特征 IRI 属 OWL 词汇表谓词，本就是该列设计语义） |
| 校验器分支 | switch(type) 七分支 | switch(predicate_iri) 七分支，复杂度相同 |
| 03 期复用 | 需新号段 | 对称新增 `AXIOM_DATA_PROPERTY_CHARACTERISTIC(43)` 即可（03 号文档定案） |
| diff 语义 | 类型集合 diff | predicate 集合 diff，等价 |

**特征谓词 IRI**（OWL 2 词汇表，Go 常量入 `internal/ontology/types.go`，proto 侧加 `OntologyPropertyCharacteristic` 枚举供前端，见 §3.2）：

```
owl:FunctionalProperty / owl:InverseFunctionalProperty / owl:TransitiveProperty /
owl:SymmetricProperty / owl:AsymmetricProperty / owl:ReflexiveProperty / owl:IrreflexiveProperty
```

每特征一行 33 型公理（subject=属性，object_id 空，value_text 空）。

**成对存储纪律**：34/35/36 为对称二元公理，沿用 01 期 21/22 型的成对行模式——(P,Q) 与 (Q,P) 各一行，usage 反查与 diff 均为 O(1) 行操作。属性断言（61，06 期）**不**成对——断言有方向性。

### 2.3 决策三：层级算法泛化——直接实例化（V1.1 修正：按 01 期实际形态落位）

源项目 02 期做了"新建 `EntityHierarchySupport` + `ClassHierarchyBuilder` 改薄委托 + 15 项单测回归守护"的重构。V1.0 本文曾预告"`hierarchy.go` 三方法生而携带 `(ontologyID, entityType, hierarchyAxiomType)` 参数"，**与 01 期实际实现不符**：本仓 01 期落的是投影入参形态（`BuildClassTree(ctx, ClassHierarchyInput{Entities, Edges})` / `SubtreeIDs(rootID, edges)` / `AssertNoCycle(targetID, parentEdges, targetParentIDs, entityNames)`，算法本身与实体类型无关），唯 `CollectHierarchyEdges(axioms)` 硬编码 20 型边。02 期实际落位：

- `CollectHierarchyEdges(axioms, edgeType)` 参数化（02 期唯一层级算法改动）——类树传 20、属性树传 30，`BuildClassTree` 以属性实体集 + 30 型边直接复用（函数名沿用 01 期，注释注明实体类型无关）；
- 以 `entityType=OBJECT_PROPERTY(20)`、`edgeType=AXIOM_SUB_OBJECT_PROPERTY_OF(30)` 实例化调用；
- 属性树**无 nav 剪枝**（骨架化是类的万级规模防御，属性量级小，全量树 + antd Tree 虚拟滚动足够，亦无"全部类"双源开关）；
- 类树既有单测作为泛化回归守护照常运行 + 属性树专项单测（多父双现/孤立成根/环检测/防御环）。

### 2.4 决策四：frame diff 公共组件复用——组合优于继承（与源同款修正）

源 01 期文档曾预告"属性族抽象**基类**"，02 期实现时修正为组合。本仓同理且更自然（Go 无继承）：

- 01 号文档 `changeset.go` 沉淀的 diff 组件（V1.1 修正：`DiffSubjectSideRelations` 01 期实现硬编码 20 型，02 期泛化签名增加 `axiomType` 参数后即为与"类/属性"无关的公共组件）：`DiffSubjectSideRelations(subject, axiomType, current, targetIDs)`（单边集合 diff + `sort_order` 重写）、`DiffSymmetricPairs`（对称成对 diff）、`DiffAnnotations`（内建注解 replace）——类服务与属性服务**均委托**；
- 02 期新增两个组件（`changeset.go` 增量）：
  - `DiffCharacteristics`：33 型主语侧按 `predicate_iri` 集合 diff（变体：以谓词列而非 object_id 为集合键）；
  - `DiffChains`：按链**内容**比对——提交含 id 且成员序列未变 → 不动；含 id 且变更 → 删旧行+增新行；无 id → 增；缺 id → 删（frame 全量替换语义）；链行编解码/投影/成员反查在 `object_property.go`（`EncodeChainMemberIDs` / `ParseChainMemberIDs` / `PropertyChainsOf` / `ChainReferrers`）；
- **不做 `AbstractPropertyService` 之类的泛化基座**：03 期数据属性与对象属性的差异面（值域类型、特征集合、frame 分区）在 03 号文档定稿前不可预估，过早抽象必错；03 期落地后重复度仍高再评估上提（Go 侧对应手段是接口抽取或泛型，不是继承）。

### 2.5 决策五：虚拟根 owl:topObjectProperty（owl:Thing 模式的镜像）

OWL 2 规定对象属性层级的顶点是 `owl:topObjectProperty`（`http://www.w3.org/2002/07/owl#topObjectProperty`）。落法与 01 期 owl:Thing 完全同构：

- **不入库**、不可编辑/删除，仅可"新建子属性"；
- 服务端树接口返回根列表，虚拟根由前端固定渲染（属性树数据为空时同样展示，对应 Protégé 空本体下仍可见 topObjectProperty）；
- 常量入 `internal/ontology/types.go`：`IRIOWLTopObjectProperty`（与 `IRIOWLThing` 并列；03 期镜像 `owl:topDataProperty`）。

### 2.6 决策六（对 06 期契约）：`AXIOM_OBJECT_PROPERTY_ASSERTION(61)` 行语义定稿

回收源 06 期文档悬置项（与源定稿一致，本仓号段对齐）。**61 行按三元组直读落行**：

```
subject_id    = 主语个体（ont_entities.id，entity_type=60）
predicate_iri = 对象属性 IRI（必须命中本本体下已声明的对象属性实体）
object_id     = 宾语个体（ont_entities.id）
value_text / lang = 空
```

- **为什么谓词走 IRI 而不是实体 id**：subject 与 object 都是实体，而 `object_id` 是行内唯一的"实体引用"槽位，必须留给**宾语个体**——个体图遍历、"谁被我引用"反查都按它走 `idx_ont_axioms_object`；谓词用 IRI 与注解断言（100）同轨，`predicate_iri` 列语义本来就是"谓词 IRI"。
- **校验纪律（06 期实施义务）**：断言创建时服务层校验 predicate_iri 命中已声明对象属性（entity_type=20）、两端个体已声明；外部/未声明属性 IRI 的断言 V1 拒绝。
- **个体 usage 反查集定稿**：个体"被引用" = `TYPE_ASSERTION(60)` 的 object_id 命中（被断型）∪ `OBJECT_PROPERTY_ASSERTION(61)` 的 **object_id 命中**（作为关系宾语）。主语侧断言属于个体自身 frame，不计入被引用。
- **个体删除策略定稿**：作为 61 行宾语的个体参与 usage 保护（force=false 拒绝并列出引用方个体）；force=true 级联删除"以我为宾语"的断言行——引用方个体的 frame 内断言随之消失，语义等价 `OWLEntityDeleter`。06 号文档回填清单见 §10。
- 62（数据属性断言）行语义仍归 03 号文档定稿。

### 2.7 推理影响声明

02 期公理全部是合法 OWL 2 DL 公理，为未来接入推理储备，但 V1 **无推理机、不做一致性检查**（本仓纯 Go 校验器只做结构校验，01 号文档决策五）：

- 展示的层级是 **Asserted 层级**（Told hierarchy），不显示 Inferred；传递/对称等特征不参与服务端建树；
- symmetric + asymmetric 同时勾选、等价与不相交并存等**语义矛盾组合不拦截**（OWL 结构合法，矛盾仅在推理时暴露；Protégé 亦不拦截）；
- 逆向链（如 P 对称且 inverseOf(Q)）等冗余组合不消除，保留建模者意图。

## 3. 数据模型

### 3.1 公理行语义总表（02 期增量）

| axiom_type | subject_id | object_id | predicate_iri | value_text | sort_order | 校验器规则（§4.4） |
|---|---|---|---|---|---|---|
| 30 子属性 | 子属性 | 父属性 | – | – | 多父保序 | 两端为已声明对象属性 |
| 31 定义域 | 属性 | **类** | – | – | 多值保序 | subject=对象属性，object=已声明**类** |
| 32 值域 | 属性 | **类** | – | – | 同上 | 同上 |
| 33 特征 | 属性 | – | 特征 IRI | – | – | predicate_iri ∈ 七特征白名单 |
| 34 逆属性 | 属性 | 伙伴属性 | – | – | – | 两端为已声明对象属性 |
| 35 等价 | 属性 | 伙伴属性 | – | – | – | 同上 |
| 36 不相交 | 属性 | 伙伴属性 | – | – | – | 同上 |
| 37 属性链 | **超属性** | – | – | `["id1","id2",…]`（有序） | 多链排序 | value_text 合法 JSON 数组、成员 ≥2、逐个命中已声明对象属性 |
| 100 注解断言 | 属性 | – | 内建谓词 | 值 | – | 复用 01 期（label/comment/deprecated） |

**属性链行语义说明**（对齐 Protégé：链公理挂在超属性名下）：

- subject_id = 超属性（链所蕴含的一方，`chain ⊑ P` 中的 P）；
- 链成员（≥2 个，**保序，不做 distinct 归一化**——源实现修订 #3：distinct 会把 `P∘P` 压成单成员而误报"链成员数不足"；允许重复如 `P∘P`，允许包含超属性自身——OWL 2 语法合法）存于 value_text JSON 数组；成员必须是本本体下已声明的对象属性；
- usage 反查与级联删除按 value_text 包含判定（§4.3），链行数量小（每属性至多几条），全量扫描可接受；
- 同一属性多条链之间用既有 `sort_order` 排序。

**渲染缓存**：`display_label` / `deprecated` 缓存同步机制复用 01 期（`ChangeApplier` 管线第 4 步），属性实体零额外处理。

### 4.2 创建 / 更新事务管线（create / update 共用，frame 全量提交）

```
1. 本体存在且启用
2. localName 合法（create）；update 忽略 local_name（不参与 diff，01 号文档 §4.4.2 语义）
3. IRI 查重（create，前置 + partial unique index 双层）         → ENTITY_IRI_DUPLICATE
4. 引用目标类型与存在性校验（ValidateRefEntities，全部为本体下已声明实体）：
     superPropertyIds / inverseIds / disjointIds / equivalentId / chains[].memberIds
       → expectedType=OBJECT_PROPERTY                            → PROPERTY_TARGET_INVALID
     domainIds / rangeIds
       → expectedType=CLASS                                      → PROPERTY_DOMAIN_INVALID / PROPERTY_RANGE_INVALID
   自引用语义（对齐 01 号文档 §3.3，各归其位）：
     superPropertyIds 含自身 → 交由环检测（HIERARCHY_CYCLIC）
     inverseIds 含自身       → PROPERTY_INVERSE_SELF_INVALID
     disjointIds / equivalentId 含自身 → PROPERTY_SELF_REFERENCE_INVALID
   （create 不做自引用校验——新实体尚无 id，01 号文档同款结论）
5. 属性环检测：hierarchy.AssertNoCycle(entityType=OBJECT_PROPERTY, edge=30)
6. chains 校验：每条长度 ≥ 2；成员保序不去重（允许 P∘P）；允许含超属性自身（§3.1） → PROPERTY_CHAIN_INVALID
7. characteristics 校验：IRI ∈ PropertyCharacteristicIRIs        → PROPERTY_CHARACTERISTIC_INVALID
8. 组装 EntityChangeSet → ChangeApplier.Apply()（乐观锁 → 公理增删 → 注解缓存同步 → 结构校验 → version+1 → 日志）
```

**update 差异计算（frame 全量替换语义，逐 section diff）：**

| section | diff 规则（组件） |
|---|---|
| superPropertyIds | `DiffSubjectSideRelations`（30 型，同 01 期父类；顺序变化重写 `sort_order`） |
| domainIds / rangeIds | `DiffSubjectSideRelations`（31/32 型，保序补 `sort_order`） |
| characteristics | `DiffCharacteristics`（33 型按 predicate_iri 集合 diff，增/删行） |
| inverseIds / disjointIds | `DiffSymmetricPairs`（34/36 型成对，镜像行同增同删） |
| equivalentId | 单值 → 对称对 diff（35 型，与 01 期类等价同款） |
| chains | `DiffChains`（§2.4：按链内容比对，含 id 未变不动 / 变更换行 / 无 id 增 / 缺 id 删） |
| 注解 | `DiffAnnotations`（label/comment 提交 null = 清空；deprecated=false = 移除断言，01 号文档语义） |

### 4.3 usage 反查与删除保护（对应 `OWLObjectPropertyUsageViewComponent` + `OWLEntityDeleter`）

**usage(P) 引用来源：**

| 引用方式 | axiom_type | 查询路径 | 引用方 |
|---|---|---|---|
| 子属性（P 是父属性） | 30 | object_id=P | 子属性实体 |
| 逆属性伙伴 | 34 | object_id=P | 伙伴属性（成对主语侧即引用方） |
| 等价伙伴 | 35 | object_id=P | 同上 |
| 不相交伙伴 | 36 | object_id=P | 同上 |
| 属性链成员 | 37 | 本体全量 37 型行 + value_text 包含 P.id | 超属性实体 |
| （06 期追加）个体断言谓词 | 61 | predicate_iri=P.iri | 主语个体（06 期入反查集，§2.6） |

**delete 语义（与 01 期 §4.5 同款产品决策）：**

- `force=false`（默认）：存在引用 → `ENTITY_IN_USE`（409）+ 引用清单（前端弹窗展示明细，引用方式中文标签）；
- `force=true`：级联删除——① 以 P 为主语的全部公理行（30/31/32/33/34/35/36/37 主语侧 + 注解 100 + DECLARATION 10）；② 以 P 为 object_id 的行（34/35/36 镜像对、30 子属性边——子属性自动变根属性）；③ value_text 含 P.id 的链行；随后软删实体行。两种路径同一事务、同一乐观锁、同一变更日志；
- 01 期类删除不会触碰属性（类的公理从不引用属性），02 期属性删除亦不触碰类——**域/值域行的删除方向是"属性删除带走域值域行"；类被删时反向清理 31/32 行属类 usage 集扩容**（§10 对 01 号文档预埋点的执行确认）。

**类 usage 集扩容（01 号文档已预告的 02 期执行点）**：`internal/ontology` 的 `ClassUsageAxiomTypes` 常量切片由 `{20,21,22}` 扩为 `{20,21,22,31,32}`——类删除保护现在能看到"被对象属性定义为域/值域"的引用；force 级联同时清理以该类为 object_id 的 31/32 行；前端类页 usage 弹窗 refTypeName 映射补 `31 定义域` / `32 值域` 标签。

### 4.4 AxiomValidator 与渲染器 02 期增量

本仓无 OWLAPI 投影（01 号文档决策五），源 §4.4 的投影分支表转译为**结构校验规则 + Manchester 渲染分支**：

**validator.go 增量**（在 01 期"引用存在性与类型匹配"总规则下细化 30~37）：

| 类型 | 校验规则 |
|---|---|
| 30 / 34 / 35 / 36 | 两端实体均存在、未删、`entity_type = OBJECT_PROPERTY(20)` |
| 31 / 32 | subject 为对象属性、object 为已声明**类**（`CLASS(10)`） |
| 33 | predicate_iri ∈ `PropertyCharacteristicIRIs` 白名单（服务层已拦，校验器兜底直改库脏数据） |

InverseOf(P Q) / EquivalentProperties(P Q) / DisjointProperties(P Q)

## 8. 验收标准与测试要点

**域内核单测**（`internal/ontology` 纯函数 + 接口桩，`go test`）：

- 层级泛化回归：**类树既有用例全绿**（hierarchy.go 参数化的回归守护）+ 属性树多父双现、孤立属性成根、环检测（自环/深链）、防御环忽略；
- 引用校验：域/值域非类拒绝、链长度/成员类型校验（含 `P∘P` 重复成员不误报）、特征 IRI 白名单、自引用三态（环/自逆/自等价自不相交）；
- diff：特征增删（`DiffCharacteristics`）、链增删改含顺序变化（`DiffChains`）、成对逆属性镜像行（`DiffSymmetricPairs`）、注解三列；
- usage 组装：五类来源计数（含链成员包含判定）；
- validator：30~37 逐类规则断言（含 37 悬空 id / 非法 JSON 拒绝）。

**端到端验收**（本地 dev 栈：容器栈 PG + `air` 起 admin + `pnpm dev` react；验证前端前先确认请求到达后端）：

1. 新建属性 P（无父）→ 树中现于 topObjectProperty 下；P 下建 C → 树呈现两层；
2. C 加第二父属性 P2 → C 双现，路径复合 key 不串；
3. P 勾选"传递性 + 对称性"→ frame 回显勾选；列表特征列显示"传递性、对称性"标签（声明序）；
4. P 定义域=类 A、值域=类 B → 编辑框回显正确；usage(P) 显示"定义域"引用来自 A；
5. 删除 P（force=false）→ 拒绝并列出 C、A、B；force=true → C 变根属性、A/B 的域值域行消失；
6. 建链 `C1 ∘ C2 ⊑ P` → 编辑回显顺序正确；删除 C2（force）→ 链行消失；
7. 双标签页并发改 P → 后提交者 409 `ONTOLOGY_VERSION_CONFLICT`；
8. **类 usage 扩容验证**：删除类 A（被 P 定义域引用）→ force=false 拒绝并显示"定义域"引用来自 P；force=true 后 P 的域行消失；
9. 菜单 113 落库、平台管理员可见（老库「菜单同步」）。

**门禁**：`make build`；`go test ./internal/ontology/...` 全绿；`pnpm run typecheck` 全绿（本期零 DDL，无 db-drift-check 增量，但 schema 未动的前提下跑一次确认无意外漂移）。
