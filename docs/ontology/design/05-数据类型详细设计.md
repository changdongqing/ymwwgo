## 1. 背景与范围

### 1.1 业务背景与产品定位

01~04 期交付了词汇表（类/对象属性/数据属性/注解属性），但**取值的"度量衡"是封闭的**：数据属性值域只能选 15 个内建 XSD 类型（`BuiltinDatatypes` 白名单），"0~100 的整数""符合 `^A\d{4}$` 的编码""非空字符串"这类业务约束无处安放——要么放宽到整数/字符串（约束失守），要么等 06 期在服务层硬编码校验（约束不进模型、不可复用、不可见）。

05 期打开**数据类型词汇表本身**——让用户像创建类一样创建"派生数据类型"（内建基类型 + facet 约束），并把它们作为值域挂到数据属性上：

| | 内建 datatype（03 期） | **派生 datatype 实体（05 期，本文）** |
|---|---|---|
| 身份 | IRI 常量（`xsd:integer` 等），不入库 | `ont_entities` 实体（`entity_type=DATATYPE(50)`，IRI 在本体 base_iri 下） |
| 词法空间 | XSD 规范固定 | **基类型词法空间 ∩ facet 约束**（如 `xsd:integer ∩ [0,100]`） |
| 存储载体 | 42 行 `value_text=IRI` | 42 行 `object_id=datatype 实体 id`（双轨激活）+ 46 行定义 |
| 声明方式 | 白名单枚举封闭集合 | 建模者按需创建（"有效年龄""国标分类码"成为可复用资产） |

产品价值按消费方排序：① **值域约束进模型**——数据属性值域可声明"integer [0,100]"并在校验期拦截所有落库字面量（62 断言，06 期个体赋值的词法闸门），约束从"口头约定"升级为"公理"；② **业务类型词汇表**——"编码""金额""手机号"等业务类型一次定义、多处引用；③ 06 期编码断言的 datatype 标注升级路径（编码值域可从 `xsd:string` 收紧为带 pattern 的"编码类型"）。

### 1.2 05 期在系列中的定位

数据类型是六类实体中的**最简实体 + 一个横切升级**：

1. **最简实体**：OWL 2 不给 datatype 任何层级、特征、成对关系——frame 只有"定义"一节（Protégé `OWLDatatypeDescriptionFrame` 全部内容仅 Datatype Definitions 一节，§1.3）。01~04 期的共享设施中仅 `changeset.go`（公理工厂 + 注解 diff）、`EntityFactory`（创建/引用校验）、`ChangeApplier`（变更事务）被复用，`hierarchy.go` **本期不用**（无树）；
2. **横切升级**：`AXIOM_DATA_PROPERTY_RANGE(42)` 行双轨激活（object_id 承载 datatype 实体）——03 号文档 §2.2 明确预留的契约点；`BuiltinDatatypes` 由 15 类型扩充为全集白名单并接管（03 号文档 §3.2 "05 期接管扩展"）；62 断言词法校验链升级（03 号文档 §2.2 预告的三段分派兑现）。

| 能力 | Protégé 对应 |

**V1 范围外（Out of Scope，写明去向）：**

- **facet 以外的 DataRange 形态**：oneOf 字面量枚举、union/intersection/complement 组合 datatype → 后续迭代（46 行 value_text JSON 预留 `kind` 判别键，届时零迁移）；
- **datatype 套 datatype（多层派生）**：定义的基类型仅限内建白名单，不允许 datatype 实体作基类型 → 后续迭代（需环检测 + 词法校验递归展开，V1 场景单层够用，§2.3）；
- **注解值 datatype 锁定**（04 号文档 §10 悬置项）：注解属性值域行 + 值类型判别列（`value_kind`）仍不动表结构，**本期维持 04 期结论不开放**（§10 回应）；
- **gYear/gMonth/duration/QName/NOTATION 等扩展内建类型**：OWLAPI `OWL2Datatype` 枚举不含（需自建词法校验器）→ 后续按需逐个开放；
- 推理层级（基于 datatype 的类型一致性检查）→ 接入 reasoner 后独立迭代；
- datatype IRI 重命名、批量导入 → 07 期及后续迭代。

## 2. 关键架构决策

### 2.1 决策一：零 DDL 实体增量——`entity_type=DATATYPE(50)` 激活，公理落 46 号段

01 号文档 proto 枚举预留全部就位：`ENTITY_TYPE_DATATYPE(50)`（`ont_entities.entity_type` 注释已载明 50=数据类型）、公理 46~49 号段空闲。本期**不新增任何表结构、无 goose 迁移**，占用 46：

```proto
// OntologyAxiomType 枚举 05 期启用值：
ENTITY_TYPE_DATATYPE = 50;                  // 既有预留，激活
AXIOM_DATATYPE_DEFINITION = 46;             // 数据类型定义：subject=datatype 实体, value_text=定义 JSON（§2.3）
// 47~49 继续预留
```

datatype 实体与类/属性共用 `DECLARATION(10)` 与 `ANNOTATION_ASSERTION(100)`（04 期双轨），创建管线零特殊化。

### 2.2 决策二（本期核心）：42 行 object_id 双轨激活——二选一、不双写、API 单形态

03 号文档 §2.2 预留的双轨契约点兑现。42 行从"仅 value_text"升级为双轨：

| 行形态 | subject_id | object_id | value_text | 语义 |
|---|---|---|---|---|
| 内建 datatype（03 期存量，不变） | 数据属性 | **NULL** | 内建白名单 IRI | 值域 = 命名内建 datatype |
| **派生 datatype（本期新增）** | 数据属性 | **datatype 实体 id** | **NULL** | 值域 = 本体声明的派生 datatype（词法空间由 46 行定义） |

**沿用 04 期 100 行双轨的同款定案（不双写）**：① 双事实源规避（datatype 实体被删后 value_text 残留则语义漂移）；② 存量为零（新增能力无迁移，读规则"object_id 优先、value_text 兜底"向下兼容）；③ 轨道互斥性天然成立（datatype 实体 IRI 恒在 base_iri 命名空间，与 `xsd:` 保留命名空间不可能重叠，无需专门校验）；④ 检索直接命中索引（datatype usage 反查走 `idx_ont_axioms_object`）。

**API 层收敛为单形态**（与 04 期 100 行显式 propertyId 不同，理由记录）：`range_iris: string[]` **保持不变**，混合承载两种轨道——内建 IRI 与 datatype 实体 IRI 都是全局唯一字符串，且 UI 侧下拉本来就是"内建 + 自定义"混合数据源（Protégé `getKnownDatatypes` 同构）。服务层 save 时按 IRI 分流归一化（**三分支**，源修订 #6 定案内化）：

```
range_iris 去重 + 剔除空白（03 期规则）后逐项分流：
  ├─ IsBuiltinDatatype(iri)                          → 42 行 value_text 轨（存量形态）
  ├─ 按 IRI 反查实体：命中且 entity_type=DATATYPE 且同本体 → 42 行 object_id 轨
  │      命中但类型不符（如类/属性实体 IRI）            → DATATYPE_RANGE_TARGET_INVALID
  │      命中但跨本体                                  → DATATYPE_RANGE_TARGET_INVALID
  └─ 未知 IRI（非内建、全局无实体）                    → DATA_PROPERTY_RANGE_INVALID（03 期既有码，语义精确化）
```

**行存储双轨与 API 单形态解耦**，前端零双轨概念。frame 回读时 object_id 轨反填实体 IRI。

### 2.3 决策三：datatype 定义 = "内建基类型 + facet 限制"单层派生，46 行单行 JSON

**定义公理落行**（对齐 37 属性链的"结构化 value_text"先例）：

```
AXIOM_DATATYPE_DEFINITION(46)：subject_id=datatype 实体 id, object_id=NULL, predicate_iri=NULL,
value_text = JSON：{"baseIri":"http://www.w3.org/2001/XMLSchema#integer",
                   "facets":[{"facet":"minInclusive","value":"0"},{"facet":"maxInclusive","value":"100"}]}
```

**决策记录：**

1. **单行 JSON 而非"一行定义 + 多行 facet"**：定义是**不可分整体**——基类型换了 facet 可能整体失效（数值 facet 挂到字符串基类型非法），拆行会产生"换了 base 还没清 facet"的中间态；单行 diff = 整体替换，无部分状态；
2. **基类型仅限内建白名单**（单层派生）：datatype 实体作基类型会引入派生链环检测、词法校验递归展开两个新问题，而常见用法（facet 收紧一个内建类型）单层已覆盖；OWL 2 允许任意深度，写明后续开放路径（§1.4）；
3. **facet 名去重（后者覆盖）**：XSD 中 pattern 允许多值（并集语义），其余 facet 单值——V1 统一按 facet 名去重，pattern 多值随后续迭代；facets 保提交序（前端展示序稳定）；
4. **定义可选**：datatype 实体允许"仅声明未定义"（46 行缺失）——对应 Protégé "signature 中有 datatype 但无 DatatypeDefinition" 的合法状态；未定义 datatype 参与 usage/校验（仅 DECLARATION），62 断言命中时词法放行（无词法空间可校验，03 号文档"其余放行"口径的自然延伸）；
5. **校验器规则**：46 行解析后的结构校验即本期校验面的形式化定义（base 为内建 datatype、facet 名合法、facet 值词法合法、适用族匹配——§4.7）。

**facet 值的类型化规则**（比对/校验时的解析口径）：长度类（length/minLength/maxLength）与位数类（totalDigits/fractionDigits）→ 非负整数；数值比较类 → decimal 族按 `big.Rat` 精确解析比较、float 族按 `float64`（Go 标准库，OWLAPI 无 BigDecimal 重载的坑在本仓不存在）；时间比较类 → 随基类型解析；pattern → 字符串正则（RE2，见 §12 #3 差异记档）。

### 2.4 决策四：内建白名单全集扩充（15 → 31）与 datatype 支撑组件接管

**扩充原则：白名单 = "词法校验可自动覆盖"的内建类型集合**（31 项 = OWLAPI `OWL2Datatype` 枚举的 29 个 XSD 成员 + `xsd:date`/`xsd:time` 自建词法特例——03 号文档既有 15 项是子集，存量零影响）。明细见 §3.2。

**刻意剔除并记档**（防"为什么没有"复查）：`rdfs:Literal`（top datatype，语义 = 任意字面量，等于不设值域行）；`rdf:langString`（03 期已定：语言文本走 62 行 lang 列）；`rdf:PlainLiteral`/`rdf:XMLLiteral`（非值域声明场景）；`owl:real`/`owl:rational`（OWL 原生数值超集，业务场景被 decimal/double 覆盖）；枚举外扩展类型（gYear/duration/QName 等，§1.4）。

**"接管"的完整定义**（03 号文档 §3.2 "05 期接管扩展"的兑现）——本仓的 datatype 支撑组件拆两个文件（对应源 `OntDatatypeSupport` 统一件的四项职责）：

```
internal/ontology/
├── lexical.go    # 扩充：BuiltinDatatypes 15→31（+Family 字段）+ 逐 Kind 词法校验（03 期既有，扩充不迁移——
│                 #   03 号文档直接建在独立文件，无"从校验器迁出"动作，前置消化）
└── datatype.go   # 新增：定义/facet 统一件
    ├── ParseDefinition(json) → DatatypeDefinition          // 脏 JSON → DATATYPE_DEFINITION_JSON_INVALID
    ├── NormalizeDefinition(def) → string                    // 固定键序、facet 名去重（后者覆盖）、value trim、空白剔除、保提交序
    ├── DiffKeyDefinition(def) → string                      // diff 比对键：归一化后 facets 按名+值排序再序列化（源修订 #7 内化：
    │                                                        //   调序提交等值 → 无操作，落库形态仍保提交序）
    ├── ValidateDefinition(def)                              // base 白名单/facet 白名单/适用族/值词法/静态冲突五规则（§3.2）
    ├── ValidateLexicalDerived(lexical, def)                 // 62 断言派生轨：base 词法 + 逐 facet 检查（§2.6）
    └── FacetFamilies / FacetWhitelist                       // facet 适用族矩阵与白名单常量
```

调用方：`validator.go`（62 词法链 §2.6、46 规则 §4.7、42 白名单校验）、`ontology_datatype_service.go`（定义保存校验 §4.2）、后续 06 期个体赋值 UI 的词法预提示（只读复用）。

### 2.5 决策五：无层级、无树——系列首个纯列表实体页

OWL 2 无 subDatatypeOf，Protégé 亦无 datatype 树（平铺列表，§1.3）。本期页面**不做左树**，全宽 `ListTable` 列表 + `DrawerForm` 编辑，`hierarchy.go` 本期零调用（首个不实例化层级参数的实体期）。与系列的一致性由其余骨架承接：贴底布局、`OntologySwitcher`、权限过滤、乐观锁交互全部沿用。

### 2.6 决策六：62 断言词法校验链升级——派生 datatype 的 facet 词法空间生效

03 号文档 §4.4 的 62 分支 datatype 推断链（首条 42 行 value_text，缺省 xsd:string）升级为三段（03 号文档 §2.2 预告的兑现）：

```
首条 42 行（按 sort_order/id 最小，03 期规则不变）：
  ├─ value_text 非空（内建轨）   → lexical.go 词法校验                 // 现状行为
  ├─ object_id 非空（派生轨）    → 取该 datatype 实体的 46 行定义：
  │      ├─ 有定义 → ValidateLexicalDerived（base 词法 + 逐 facet 检查）
  │      └─ 未定义 → 放行                                          // 无词法空间（03 号文档口径）
  └─ 无 42 行                   → xsd:string 缺省                    // 不变
```

- **facet 检查语义**：词形 ∈ base 词法空间，且逐个满足 facet 约束（规则表见 §3.2）；
- **写入方仍为零**：62 断言行 06 期才产生，但校验分支与校验链本期落地（"分支先行无副作用"同款），06 期零改动可用；
- 61 断言（对象属性）、100 注解（plain literal）不受影响；42 行本身不产生字面量，词法闸门只在 62。

### 2.7 推理影响声明

与 01~04 期同款：V1 无推理机、不做一致性检查。datatype 定义公理在 DL 语义下可被 reasoner 用于字面量类型判定（未来"类型一致性检查"的真实收益点）；本期 facet 约束的实际执行面是**校验期词法校验**（服务级推理替代，与 03 期 62 词法校验同源）。多值域交集为空（`string ∩ integer[0,100]`）、facet 组合静态合法但语义不可满足（pattern 与区间不可同时满足）等场景**允许保存**，矛盾在推理期暴露。

### 3.2 白名单全集 / facet 体系 / 校验规则

**`BuiltinDatatypes` 15 → 31**（新增 16 项；既有 15 项 IRI/Kind 不变，存量零影响；结构体加 `Family` 字段）：

| NUMERIC_DECIMAL 数值·十进制 | 14 | decimal, integer, long, int, short, byte, nonNegativeInteger, nonPositiveInteger, positiveInteger, negativeInteger, unsignedLong, unsignedInt, unsignedShort, unsignedByte | 后 7 项 |
| NUMERIC_FLOAT 数值·浮点 | 2 | float, double | – |
| STRING 字符串 | 7 | string, normalizedString, token, language, Name, NCName, NMTOKEN | 后 6 项 |
| BINARY 二进制 | 2 | hexBinary, base64Binary | 全部 |
| TEMPORAL 时间 | 4 | date, dateTime, dateTimeStamp, time | dateTimeStamp |

新增 Kind 的词法实现（`lexical.go` 扩充，Go 标准库）：非正/正/负整数与无符号族 → `strconv.ParseInt/ParseUint` + 符号判定；normalizedString（无换行/制表）/ token（首尾无空白、无连续空白）/ language（`[a-zA-Z]{1,8}(-[a-zA-Z0-9]{1,8})*`）/ Name / NCName / NMTOKEN → 正则；hexBinary（`[0-9A-Fa-f]*` 且偶长度）/ base64Binary（`encoding/base64` 词法校验）→ 正则 + 标准库；dateTimeStamp → RFC3339 且**必须**带时区。

**facet 白名单 10 种**（`datatype.go` 的 `FacetWhitelist` + `FacetFamilies`；剔除 `whiteSpace`（词法校验零产出）、`langRange`（语言文本走 lang 列，03 号文档同源理由））：

| facet | IRI（`…#` 下） | 适用族 | facet 值校验 |
|---|---|---|---|
| length / minLength / maxLength | 同名 | STRING / BINARY | 非负整数 |
| pattern | pattern | **全部族** | 合法 Go 正则（`regexp.Compile`，RE2——差异记档 §12 #3） |
| minInclusive / minExclusive / maxInclusive / maxExclusive | 同名 | NUMERIC_DECIMAL / NUMERIC_FLOAT / TEMPORAL | 值 ∈ 基类型词法空间 |
| totalDigits / fractionDigits | 同名 | NUMERIC_DECIMAL | 非负整数 |

**保存期静态冲突检查**（服务层，`DATATYPE_FACET_CONFLICT`；五规则，源修订 #3 的边界内化）：

| # | 规则 | 依据 |
|---|---|---|
| 1 | minInclusive 与 minExclusive 并用 | XSD：下界二选一 |
| 2 | maxInclusive 与 maxExclusive 并用 | XSD：上界二选一 |
| 3 | length 与 minLength/maxLength 并用 | XSD：定长与区间二选一 |
| 4 | min > max 恒冲突；**min == max 且任一侧 exclusive 亦冲突**（如 `x > 2.5 ∧ x ≤ 2.5` 值空间为空）——含混合 inclusive/exclusive | 值空间为空 |
| 5 | minLength > maxLength | 同上 |

**62 断言 facet 检查规则**（校验期，`ValidateLexicalDerived`；不满足 → `AXIOM_INVALID`）：

| facet | 检查 |
|---|---|
| pattern | `regexp.MatchString(facetValue, lexical)` |
| 长度 3 | `utf8.RuneCountInString(lexical)` 与 [minLength, maxLength]（或 length 等值）比较（码点计；二进制族按字节计数的 XSD 精确语义记为后续精化项——源修订 #9 口径） |

### 4.2 datatype 创建 / 更新事务管线（frame 全量提交）

```
1. 本体存在且启用
2. localName 合法（create）；update 忽略 local_name
3. IRI 查重（create，双层）                                     → ENTITY_IRI_DUPLICATE
4. 定义校验（definition 字段非 nil 时，§5 语义）：
     base_iri ∈ 内建白名单                                      → DATATYPE_BASE_INVALID
     facets 非空而 base_iri 缺失                                → DATATYPE_BASE_INVALID
     facet 名 ∈ FacetWhitelist                                  → DATATYPE_FACET_INVALID
     基类型族 ∈ facet 适用族                                     → DATATYPE_FACET_INVALID
     facet 值词法合法（长度非负整数/pattern 合法正则/比较值 ∈ base 词法空间）→ DATATYPE_FACET_INVALID

### 4.3 定义行 diff（46 单行整体替换）

```

### 4.4 数据属性侧双轨改造（03 期服务增量，本期横切重点）

## 8. 验收标准与测试要点

**域内核单测**（`internal/ontology` 纯函数 + 接口桩，`go test`；本期是首个不引用 `hierarchy.go` 的实体测试）：

- 创建：工厂规则、IRI 查重、仅声明未定义态保存与回显；
- 定义校验：基类型白名单外拒绝、facet 白名单外拒绝、族不适配拒绝（数值基类型 + length / 字符串基类型 + minInclusive 等代表性用例）、facet 值词法拒绝（非负整数列传负数、pattern 非法正则、比较值不在 base 词法空间）、静态冲突五规则逐条拒绝（含 min==max + exclusive 边界）；
- 定义 diff：新增 / 等值无操作（DiffKey 调序不敏感，断言**行 id 不变**而非版本不变——源修订 #8 内化）/ 修改 / 显式空定义清空 / nil 跳过；facet 名去重（后者覆盖）与保序；
- 词法：新增 16 Kind 逐项正/反例（无符号族负数拒绝、token 连续空白拒绝、language 形态、hexBinary 奇长度拒绝、base64 词法、dateTimeStamp 无时区拒绝）；
- facet 检查：数值比较（big.Rat 精确）、长度码点、位数按写形（`"1.50"` fractionDigits=2）、pattern 命中/不命中、时间比较（dateTime 墙钟 / dateTimeStamp 绝对时刻）；
- **数据属性双轨**：save 分流三分支（内建 → value_text 轨 / 实体 IRI → object_id 轨 / 类型不符与跨本体拒绝 / 未知 IRI 拒绝）、frame 回读 object_id→IRI 反填、双轨混合值域 diff（删内建补派生、sort_order 顺排）；

- 乐观锁冲突。
