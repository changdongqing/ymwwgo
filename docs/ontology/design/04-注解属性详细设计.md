## 1. 背景与范围

### 1.1 业务背景与产品定位

01~03 期交付了"骨架词汇"（类/对象属性/数据属性），但其元数据层是**封闭的**：实体只能挂内建注解（rdfs:label / rdfs:comment / owl:deprecated / skos:notation，由表单专属字段承载）。04 期打开**注解词汇表本身**——让用户像创建类一样创建"注解属性"，并把它挂到任意实体上：

| | 03 数据属性 | **04 注解属性（本文）** |
|---|---|---|
| 连接什么 | 个体 → 字面量（"张三 age 42"） | 任意实体 → 字面量（"动物 曾用码 A01"） |
| 语义地位 | 断言公理，进入 OWL 语义（值域、函数性约束） | **注解公理，零推理语义**（描述性元数据，推理机不处理） |
| 谁在用 | 06 期个体断言的谓词来源 | 建模元数据：来源引用、编码别名、状态标记、SKOS 词汇扩展 |
| 特征/域值域 | 函数性 / 域 / 值域 | **无**（OWL 2 不给注解属性任何逻辑特征，§1.3） |

产品价值：① **元数据可扩展**——"曾用码""数据来源""同义标签"等业务元数据不再硬编码进表单，由建模者自定义；② **06 期赋码体系的承载面**——"曾用码"注解、类编码别名等全部走本期通用机制；③ SKOS/DC 等外部词表的对接基座（本期建机制，词表导入随 07 期及后续迭代）。

### 1.2 04 期在系列中的定位

01 号文档判定：注解属性是"属性机制的最简退化子集"。01~03 号文档沉淀的可复用设施（`hierarchy.go` 参数化建树、`changeset.go` diff 组件、`EntityFactory.ValidateRefEntities`）全部直接复用。本期真正的**新增量只有两块**：

1. 注解属性实体本身的管理（镜像 02/03 期形态做减法）；
2. **`AXIOM_ANNOTATION_ASSERTION(100)` 谓词双轨激活**（`ont_axioms.object_id` 承载自定义谓词）——01 号文档 DDL 注释与校验器白名单预留的本期契约点，以及随之而来的**六类实体通用注解区**（各实体 frame 从"内建专属字段"升级为"内建字段 + 任意自定义注解列表"）。

**V1 范围外（Out of Scope，写明去向）：**

- 注解属性的 rdfs:domain / rdfs:range 公理 → 后续迭代（Protégé frame 有此二节；V1 无 IRI 值与 datatype 锁定需求，行模式可复用 41/42 的"主语侧关系/值文本"双形态）；
- **IRI 型注解值**（rdfs:seeAlso 指向外部资源）与匿名个体值 → 后续迭代：`ont_axioms` 现有列无法区分"无语言字面量"与"IRI 值"（value_text 同为字符串），需引入值类型判别列（如 `value_kind`），本期不动表结构；
- 内建注解属性全集（rdfs:seeAlso / owl:versionInfo 等未启用谓词）开放为可选注解 → 后续迭代（`types.go` 内建谓词常量扩充即可，无结构改动；V1 四内建谓词已由专属字段承载）；
- 公理级注解（替换式 `getAnnotatedAxiom`）与本体 header 注解 → 后续迭代（公理不可变 + 替换式修改的存储模型已天然兼容，届时零迁移）；
- 显示名谓词偏好（skos:prefLabel 纳入）与语言偏好面板 → 后续迭代（§2.6 常量留缝）；
- SKOS/DC 外部词表批量导入、注解属性 IRI 重命名 → 07 期及后续迭代；
- 推理层级 → 注解公理无推理语义，**永不存在此需求**（与 01/02/03 的"接入 reasoner 后开放"不同）。

## 2. 关键架构决策

### 2.1 决策一：零 DDL 实体增量——`entity_type=ANNOTATION_PROPERTY(40)` 激活，公理落 50 号段

01 号文档 proto 枚举预留全部就位：`ENTITY_TYPE_ANNOTATION_PROPERTY(40)`、`AXIOM_SUB_ANNOTATION_PROPERTY_OF(50)`。本期**不新增任何枚举值、不动任何表结构、无 goose 迁移**，激活即用：

```proto
// 既有（01 号文档 §3.7 预留），本期启用：
ENTITY_TYPE_ANNOTATION_PROPERTY = 40;   // 注解属性
AXIOM_SUB_ANNOTATION_PROPERTY_OF = 50;  // 子注解属性：subject=子属性, object_id=父属性（多行=多父）
```

### 2.2 决策二（本期核心）：`AXIOM_ANNOTATION_ASSERTION(100)` 谓词双轨激活——自定义谓词走 `object_id`，二选一、不双写

100 行的谓词从"仅 predicate_iri"升级为双轨（01 号文档 §3.6 校验器白名单与 `ont_axioms.object_id` 列注释预留的契约点）：

| 行形态 | subject_id | object_id | predicate_iri | value_text | lang |
|---|---|---|---|---|---|
| 内建谓词（01~03 期存量） | 被注解实体 | **NULL** | rdfs:label / rdfs:comment / owl:deprecated / skos:notation | 值 | zh（label/comment 现状）/ 空 |
| **自定义谓词（本期新增）** | 被注解实体 | **注解属性实体 id** | **NULL** | 值 | 可选（空 = 无语言） |

**为什么谓词只占 object_id、不同时写 predicate_iri（不双写）：**

1. **无存量迁移负担**：自定义注解是全新能力，不存在"旧行只有 value_text"的兼容问题（42 行双轨是为 05 期 datatype 实体化预留的存量兼容路径，两者场景不同）；新增能力直接定死单轨最干净；
2. **双写引入双事实源**：若 predicate_iri 与 object_id 并存，注解属性实体被删后 predicate_iri 残留，行"还能渲染但实体已亡"，语义漂移——正是 01 号文档 §2.2 否决 `parent_id` 冗余列的同款理由；
3. **统一解析规则**：读路径一律"object_id 非空 → 解析实体取 IRI；否则 predicate_iri"，frame 渲染、校验器、usage 反查三处共用（62 行"谓词占 object_id"的同款取舍——object_id 槽位空闲且"按谓词反查"是高频路径时，实体引用优于 IRI 字符串）；
4. **检索直接命中索引**："该注解属性被哪些实体使用"（usage 反查、词表维护视角）走 `idx_ont_axioms_object (ontology_id, object_id)`，免 IRI 二次解析（01 号文档 §3.5 预告的收益兑现）。

**内建谓词行不动**：predicate_iri 路径原样保留（displayLabel/comment/deprecated/notation 专属字段机制不变，01 号文档语义不变），存量数据零迁移。

**冲突不可能性**：自定义注解属性实体的 IRI 恒在 `base_iri` 命名空间下，与内建词表 IRI 天然不相交，双轨互斥性无需专门校验（base_iri 被误设为保留词表命名空间的极端场景见 §7 #12）。

### 2.3 决策三：虚拟根 owl:topAnnotationProperty；内建谓词不入树、不入库

**虚拟根**：与 01/02/03 期系列同构——`owl:topAnnotationProperty`（`http://www.w3.org/2002/07/owl#topAnnotationProperty`）作为前端固定渲染的虚拟根，不入库、不可编辑删除、仅可"新建子属性"。常量入 `internal/ontology/types.go`：`IRIOWLTopAnnotationProperty`。

**与 Protégé 的刻意差异**（记录决策理由，与源同款）：Protégé 注解属性树是多根并列 + 无条件展示 8 个内建注解属性根。本系统**不照搬**，理由：

1. **系列一致性**：类树（owl:Thing）/ 对象属性树 / 数据属性树均为"单虚拟根 + 声明实体"模式，注解属性树独用多根形态会破坏用户心智与前端树组件的复用；
2. **内建谓词不入库**：`ont_entities` 只登记本体内声明的实体（IRI 在 base_iri 下），rdfs:label 等外部词表 IRI 若入库则成为"每个本体重复种子、可被误删、跨本体不共享"的伪实体——01 期以来"内建谓词 = 常量 + 专属表单字段"的心智保持不变；
3. **避免双入口**：若 rdfs:label/rdfs:comment 出现在注解属性树并可选入自定义注解区，将与既有专属字段形成同一谓词两个编辑入口（数据漂移源）。V1 自定义注解区的谓词候选**仅列本体内声明的注解属性实体**（§6.4），内建谓词走专属字段，职责互斥。

Protégé 多根形态的真实收益（"用户永远能看到/选中 rdfs:label"）由专属字段 + 后续迭代的"内建谓词全集开放"承接（§1.4）。

### 2.4 决策四：注解值 V1 仅字面量（可选语言标签），IRI 值/匿名个体范围外

- **值 = 字面量**：`value_text` 存词形，`lang` 列可选（空 = 无语言字面量）。语言标签不校验 BCP-47 合法性（Protégé 用 `LangTagEditor` 联想 ISO 码表；V1 自由文本输入，大小写原样存储，非空校验仅拒绝空白）；
- **字面量 datatype 一律 plain literal 语义**：不引入 datatype 选择（Protégé 的 datatype 下拉 + 按属性 range 锁定依赖 05 期 datatype 实体化，届时随 IRI 值一并评估）；
- **同属性多值合法**：OWL 注解断言是集合语义，重复值合法（Protégé 同款，每条断言独立一行）——前端注解区支持同属性多行；
- **IRI 值/匿名个体**：范围外（§1.4，需值类型判别列）；自定义注解区不提供值类型切换。

### 2.5 决策五：通用注解区（AnnotationListEditor）一次下沉，六类实体受益

Protégé `OWLAnnotationsFrame` 以实体 IRI 为根、六类实体共享同一注解 frame 的机制，映射为本期前端**共享组件 + 后端共享 diff**：

- 前端：`pages/app/ontology/components/AnnotationListEditor.tsx`——行式编辑器（注解属性下拉 + 值输入 + 语言输入 + 删除），被 01/02/03 期三个既有 Drawer 与本期注解属性 Drawer 共用；06 期个体表单零成本复用；
- 后端：`changeset.go` 新增 `AppendCustomAnnotationAxioms` / `DiffCustomAnnotations` 通用 diff（§4.3），被 01/02/03/04 四个服务调用；
- 契约：四个实体的 Frame 消息统一追加 `annotations` 数组、Create/Update 请求统一追加 `annotations` 字段（语义见 §5）；
- **存量三面（类/对象属性/数据属性）的表单与 frame 同批升级**——这是 04 期"机制期"的本质：注解属性页是词汇表的管理面，通用注解区才是能力的消费面，二者缺一不可。

### 2.6 决策六：显示名渲染规则——常量留缝、功能不扩（01 号文档预告的兑现口径）

01 号文档 §7 预告 04 期"实体渲染规则升级（可配置 label 谓词）"。兑现为**架构留缝**：

- `applier.go` 注解缓存同步（01 号文档 §3.4 第 4 步）中，label 谓词从硬编码 `PredicateRDFSLabel` 改为常量切片 `DisplayLabelPredicates = []string{PredicateRDFSLabel}`（单元素，语义与现状完全等价），为后续把 skos:prefLabel 纳入显示名候选（Protégé `OWLRendererPreferences` 偏好列表的对等物）留出唯一改点；
- **UI 不开放配置**：显示名谓词顺序、语言偏好面板均为范围外（§1.4），等 06 期多语言场景驱动再开；
- displayLabel 缓存同步只认 predicate_iri 路径的 rdfs:label 行——自定义注解行 predicate_iri=NULL，**结构上不可能**干扰渲染缓存（§2.2 双轨互斥的直接收益）。

### 2.7 决策七：不上提属性族抽象（03 号文档 §2.4 定案沿用）

03 号文档已定案不建属性族公共基座，并明确"04 注解属性是最简退化子集、不进属性族"。本期沿用：`ontology_annotation_property_service.go` 独立实现，复用共享组件，差异面（无特征、无域值域、无双伙伴、多一个通用注解 diff）本就是"减法 + 一个新方法"，抽象无收益。

**差异矩阵（实现对照，03 → 04 的全部改点）：**

| 维度 | 03 数据属性 | 04 注解属性 | 复用度 |
|---|---|---|---|
| entityType / 层级边公理 | 30 / 40 | 40 / 50 | `hierarchy.go` 直接复用 |
| 定义域 / 值域 | 41 / 42 | **无** | 减法（OWL 2 无注解属性域值域的 V1 需求，§1.4） |
| 特征 | 43（函数性） | **无** | 减法（OWL 2 无注解属性特征） |
| 等价 / 不相交 | 44 / 45 | **无** | 减法 |
| 逆属性 / 属性链 | 无 | 无 | 同 |
| **自定义注解区** | 无 | **frame annotations 数组 + `DiffCustomAnnotations`** | 本期新增，六类实体共用（§2.5） |
| usage 反查 | 40/44/45 | **50 + 100（object_id 路径）** | usage 组装复用 |
| 虚拟根 | owl:topDataProperty | owl:topAnnotationProperty | 前端固定渲染模式复用 |

### 2.8 推理影响声明

注解公理在 OWL 2 中**零推理语义**（推理机不读取注解做一致性检查，Protégé 同款行为）；子注解属性关系仅构成词表组织层次，不产生任何逻辑蕴含。本期公理全部是"描述性元数据"，本仓无推理机的前提下无新增语义负担，未来接入推理机也不改变其行为——注解属性是六类实体中唯一"推理零相关"的一类。

## 3. 数据模型

### 3.1 公理行语义总表（04 期增量）

| axiom_type | subject_id | object_id | predicate_iri | value_text | lang | 校验器规则（§4.5） |
|---|---|---|---|---|---|---|


```
入参 annotations: [{ property_id, value, lang }]
前置校验（diff 前，服务层统一执行）：
  1. property_id 逐个 ValidateRefEntities(ontologyID, ids, ANNOTATION_PROPERTY, ANNOTATION_PROPERTY_TARGET_INVALID)
  2. value 空白（strings.TrimSpace 后为空）→ ANNOTATION_VALUE_INVALID

diff 键：(object_id, value_text, lang) 三元组——同属性多值天然支持（§2.4）
  删除：存量自定义行（object_id 非空的 100 行）中键 ∉ 目标集合 → DELETE
  新增：目标集合中键 ∉ 存量 → ADD
边界语义：**全量替换**——annotations 为 nil/空（protojson 对 repeated 字段的"缺失 vs 显式空数组"
  区分不可靠，见 §12 转译差异 #1）统一视为"目标集合为空"= 清空全部自定义注解；
  与 01 期内建注解"null = 清空"的 frame 全量提交语义对齐。

```

### 4.4 usage 反查与删除保护（对应 `OWLEntityUsageViewComponent` + `OWLEntityDeleter`）

**usage(P) 引用来源（无域值域/伙伴扫描——注解属性没有这些关系）：**

| 引用方式 | axiom_type | 查询路径 | 引用方 |
|---|---|---|---|
| 子注解属性（P 是父属性） | 50 | object_id=P | 子属性实体 |
| 被注解（P 是自定义谓词） | 100 | object_id=P | 被注解实体（主语） |

**delete 语义（与 01/02/03 期同款）：**

- `force=false`（默认）：存在引用 → `ENTITY_IN_USE`（409）+ 引用清单（前端标签：子注解属性 / 被注解）；
- `force=true`：级联删除——① 以 P 为 object_id 的行（50 子属性边、他人挂的自定义注解断言）；② 以 P 为主语的全部公理行（50 父边 + 100 自身注解 + DECLARATION 10）；随后软删实体行。同一事务、同一乐观锁、同一变更日志；
- **被注解实体不受影响**：删注解属性只带走"以 P 为谓词"的断言行，被注解实体本身及其内建字段注解完好（对齐 `OWLEntityDeleter` "删提及实体的公理"语义）。

### 4.5 AxiomValidator 与渲染器 04 期增量

**validator.go 增量：**

| 类型 | 校验规则 |
|---|---|
| 50 | 两端实体均存在、未删、`entity_type = ANNOTATION_PROPERTY(40)` |
| 100（升级，兼容性） | 谓词解析双轨：`object_id` 非空 → 实体必须是本本体已声明**注解属性**（否则 `AXIOM_INVALID`"注解谓词必须是注解属性实体"——服务层已拦，校验器兜底直改库场景）；否则 `predicate_iri` 非空 → ∈ 内建白名单（存量行为，不变）；二者皆空 → `AXIOM_INVALID`（01 号文档 §3.6 既有规则）。值构造：`lang` 非空仅要求 ≤16 字符（01 号文档规则），`value_text` 非空白 |

**render.go 增量：**

```

Annotation(张三, rdfs:label, "张三"@zh)            // 内建谓词路径（predicate_iri）
Annotation(动物, ex:formerNotation, "A01")         // 自定义谓词路径（object_id → 实体 IRI 解析）
```

## 7. 异常与边界场景清单

| # | 场景 | 行为 |
|---|---|---|
| 1 | IRI 重复（同名注解属性） | `ENTITY_IRI_DUPLICATE`，表单局部名红字；partial unique index 兜底并发 |
| 2 | 环：把子孙属性设为父属性（含自环） | `HIERARCHY_CYCLIC`，环路径文字 |

| 4 | 自定义注解谓词不是本体内注解属性实体（手写请求绕过前端） | `ANNOTATION_PROPERTY_TARGET_INVALID`（服务层前置）+ 校验器类型兜底（§4.5） |
| 5 | 自定义注解值为空白（trim 后空串） | `ANNOTATION_VALUE_INVALID`，行内红字 |
