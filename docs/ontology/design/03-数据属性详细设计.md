## 1. 背景与范围

### 1.1 业务背景与产品定位

02 期交付了"个体 → 个体"的关系词汇表（对象属性）；03 期交付"**字段词汇表**"——把业务对象的取值字段（如"姓名""年龄""编码""注册日期"）定义为可约束、可复用的建模资产。二者是 Protégé 的经典二分（02 号文档 §1.1）：

| | 对象属性（02 期） | **数据属性（03 期，本文）** |
|---|---|---|
| 连接什么 | 个体 → **个体**（"张三 locatedIn 华东区"） | 个体 → **字面量**（"张三 age 42"） |
| 值域 | 类（个体的类型约束） | **数据类型**（字面量的词法约束，05 期实体化的契约点） |
| 特征 | 七种全支持 | **仅函数性**（一个个体在某数据属性上至多一个值） |
| 逆属性 / 属性链 | 有 | **无**（OWL 2 语言约束，见 §2.3） |

产品价值按消费方排序：① 06 期个体断言的谓词来源——**06 期个体业务编码就是一条数据属性断言**（两级编码体系的"个体编码"层）；② 类/个体的结构化字段定义（表单生成的远期基础）；③ 函数性特征为"一对一取值"提供建模期约束。

### 1.2 03 期在系列中的定位

数据属性是"属性族的第二个实例"。本仓 01/02 号文档已把可复用设施全部落位（`hierarchy.go` 参数化建树、`changeset.go` 共享 diff、`EntityFactory.ValidateRefEntities` 引用校验）。本期工作主体是**照 02 期形态做增量实例化 + 三处真正的差异点**（值域类型、特征集合、62 行语义定稿），并回收源 06 期文档悬置的编码断言行语义（§2.6）。

- 值域的 facet 限制（`xsd:pattern` / `minInclusive` 等 DataRange 组合）与自定义 datatype 实体 → **05 数据类型期**（42 行 `object_id` 双轨已在 §2.2 预留，05 号文档兑现）；

- 断言字面量的词法预校验放服务层 → 不做，**词法校验收敛在校验器**（§4.4，服务层不重复造词法校验——本仓与源在此点同构：校验器兜底而非服务层前置）。

## 2. 关键架构决策

### 2.1 决策一：零 DDL 增量——`entity_type=DATA_PROPERTY(30)`，公理落 40~45 号段

01 号文档 proto 枚举预留 40~45，本期按需激活，**不动 04 期（50）与 06 期（60~62）**（与源一致）：

```proto
// OntologyAxiomType 枚举 03 期启用值：
AXIOM_SUB_DATA_PROPERTY_OF         = 40;  // 子数据属性：subject=子属性, object_id=父属性
AXIOM_DATA_PROPERTY_DOMAIN         = 41;  // 定义域：subject=属性, object_id=类（多行=多定义域）
AXIOM_DATA_PROPERTY_RANGE          = 42;  // 值域：object_id=NULL, value_text=内建 datatype IRI（多行=多值域；05 期双轨 object_id 预留）
AXIOM_DATA_PROPERTY_CHARACTERISTIC = 43;  // 特征（泛型）：predicate_iri 区分（V1 仅函数性一种）
AXIOM_EQUIVALENT_DATA_PROPERTIES   = 44;  // 等价：成对 (P,Q)+(Q,P)
AXIOM_DISJOINT_DATA_PROPERTIES     = 45;  // 不相交：成对
// 46~49 继续预留（05 期）
```

（02 号文档 §10 建议的槽位 43=特征、44/45 顺延，与本文一致。）

### 2.2 决策二：值域存储 = `value_text` 存内建 datatype IRI（05 期 `object_id` 双轨预留）

数据属性的值域是 DataRange。V1 只支持**命名内建 XSD datatype**，落行方案：

```
AXIOM_DATA_PROPERTY_RANGE(42)：subject_id=属性, object_id=NULL,
                              value_text=datatype IRI（如 http://www.w3.org/2001/XMLSchema#integer）
                              多行=多值域（OWL 交集语义）
```

**为什么不指 datatype 实体（object_id）**：datatype 实体化管理是 **05 期**的交付，而 03 期先行的消费方（06 期编码断言）只需要 `xsd:string` 等固定词汇——内建 XSD 类型是**封闭集合**（OWL 2 规范定义），用 IRI 常量 + 白名单（`BuiltinDatatypes`，§3.2）即可校验，**不产生对 05 期的循环依赖**。

**05 期双轨升级路径**（本决策预留的契约点，05 号文档兑现——源 05 期已验证的最终态在此预告，防各期口径漂移）：自定义 datatype（枚举/facet 限制）在 05 期注册为实体后，42 行允许 `object_id=datatype 实体 id`（object_id 与 value_text 二选一），值域解析升级为三分支（内建 IRI → value_text 轨；本本体 DATATYPE 实体 → object_id 轨；未知 IRI / 类型不符 → 各自专属错误码），frame/page/diff 统一按 IRI 投影（object_id 反填实体 IRI）；62 断言词法校验随之升级为三段分派（内建 → 词法校验；派生且有定义 → base 词法 + facet 检查；未定义 → 放行），词法实现迁移至 05 期的 datatype 支撑组件。与 01 期 skos:notation 双轨、04 期注解属性双轨完全同构的演进模式。

**值域多值**：对齐 Protégé frame 的多行 Range 与 OWL 交集语义；典型场景单值，UI 多选兼容。

### 2.3 决策三：特征仅函数性；无逆属性、无属性链（语言约束而非产品取舍）

- **特征**：OWL 2 中数据属性仅支持 `owl:FunctionalProperty`（逆函数性等六种是对象属性专属；Protégé 特征面板源码亦只有单个 Functional 复选框）。存储复用 02 期泛型模式——`43 型 + predicate_iri=owl:FunctionalProperty`（Go 常量直接复用 `PropertyCharacteristicIRIs[0]`，不为单值新建常量组）；UI 单复选框；
- **无逆属性**：OWL 2 规定 `InverseOf` 仅适用对象属性（数据属性的字面量宾语没有个体身份可反向导航）；V1 不建模，Create/Update 请求不设 `inverse_ids`；
- **无属性链**：`SubPropertyChainOf` 仅适用对象属性；V1 不建模，请求不设 `chains`；
- 函数性的产品语义："每个个体在该字段上至多一个值"——是 06 期个体表单/编码唯一性的建模期约束之一（非唯一性本身，编码唯一性仍由 06 期服务层按值校验）。

### 2.4 决策四：不上提属性族公共服务（01 号文档预告的最终定案）

01 号文档 §7 曾预告"属性族抽象"，02 号文档 §2.4 修正为"组合优于继承，03 期落地后再评估"。**本期评估结论：不建公共接口/泛型基座**（Go 侧对应手段本是接口抽取或泛型服务，也不采用），理由记档（与源同款）：

1. "属性族"只有 **02/03 两个成员**（04 注解属性是最简退化子集、06 个体是纯组合，都不进属性族），为两个成员建抽象层收益有限；
2. 二者差异恰好集中在**最难抽象的两侧**：值域（实体引用 vs datatype IRI + 白名单）与特征集合（七种 vs 一种）——抽象后必然出现大量 hook 方法，可读性反而下降；
3. 真正的共性（单边关系 diff、成对 diff、注解 diff、建树/环检测、usage 组装、分页聚合）**已经**通过 `changeset.go` / `hierarchy.go` / `EntityFactory.ValidateRefEntities` 三个共享组件覆盖，剩余重复是各自 frame 的"差异面"本身；
4. 02/03 两个 service 文件的单测分别守护两个实现，复制-适配的成本低于维护间接层。

**差异矩阵（实现对照，02 → 03 的全部改点）：**

| 维度 | 02 对象属性 | 03 数据属性 | 复用度 |
|---|---|---|---|
| entityType / 层级边公理 | 20 / 30 | 30 / 40 | `hierarchy.go` 直接复用（参数不同） |
| 定义域 | 31（object_id=类实体） | 41（同构） | `DiffSubjectSideRelations` 直接复用 |
| **值域** | 32（object_id=类实体） | **42（value_text=datatype IRI + 白名单）** | 差异点：行组装/校验/校验器规则 |
| **特征** | 33（七种，predicate_iri 区分） | **43（仅 FUNCTIONAL 一种）** | 同模式，集合不同 |
| 逆属性 / 属性链 | 34 / 37 | **无** | 减法 |
| 等价 / 不相交 | 35 / 36 成对 | 44 / 45 成对 | `DiffSymmetricPairs` 直接复用 |
| usage 反查 | 30/34/35/36 + 37 链扫描 | **40/44/45（无链扫描；06 期追加 62）** | usage 组装复用 |
| 虚拟根 | owl:topObjectProperty | **owl:topDataProperty** | 前端固定渲染模式复用 |

### 2.5 决策五：虚拟根 owl:topDataProperty（owl:topObjectProperty 模式镜像）

OWL 2 数据属性层级顶点为 `owl:topDataProperty`（`http://www.w3.org/2002/07/owl#topDataProperty`）。落法与 01/02 期虚拟根同构：不入库、不可编辑删除、仅可"新建子属性"、服务端返回根列表、前端固定渲染（属性树数据为空时同样展示）。常量入 `internal/ontology/types.go`：`IRIOWLTopDataProperty`。

### 2.6 决策六（对 06 期契约）：`AXIOM_DATA_PROPERTY_ASSERTION(62)` 行语义定稿

回收源 06 期文档悬置项。62 行按"谓词实体 + 字面量"落行：

```
subject_id    = 主语个体（entity_type=60）
object_id     = 数据属性实体 id（entity_type=30）——谓词走实体引用
value_text    = 字面量词形（lexical form）
predicate_iri = 空
lang          = 语言标签（仅语言文本场景，如 zh；有值时字面量按 rdf:langString 处理）
```

- **为什么谓词走实体 id 而非 IRI（与 61 相反）**：62 行的宾语是字面量（非实体），`object_id` 槽位空闲，让给谓词实体——"按属性查断言"（编码检索、06 期个体 frame 属性区渲染）直接走 `idx_ont_axioms_object (ontology_id, object_id)` 索引，免 IRI 二次解析。61/62 的取舍各自最优：61 两端皆实体、谓词让位给宾语（02 号文档 §2.6）；62 宾语是字面量、谓词占用 object_id。
- **datatype 不落列**：字面量的数据类型由**所在属性的 42 值域行推断**（校验期取该属性第一条 42 行的 value_text，缺省 `xsd:string`）；`lang` 有值时按语言文本（rdf:langString）处理、忽略值域推断。避免字面量 datatype 与属性值域双事实源漂移。
- **词法合法性由校验器显式执行**（源修订 #1 内化，本仓形态）：源实现实证 OWLAPI `getOWLLiteral(lexical, datatype)` 构造时**并不**校验词形（仅 null 检查），"构造即抛"假设不成立——本仓无 OWLAPI，词法校验本来就要自己写，不存在该坑，但**纪律相同**：词法校验只在校验器做（§4.4 的 `lexical.go` 按类型族用 Go 标准库校验），服务层不做词法预校验（§1.4），非法词形在校验期拒绝并回滚；
- **本期落地校验器 62 分支**（个体实体 06 期才有写入方，分支先行无副作用），06 期服务实现时零改动可用；
- **编码断言落点确认**（06 期回收）：编码 = 数据属性断言，属性实体（如 `ex:code`，值域 xsd:string）由 06 期按 03 期常规流程创建即可，无需 03 期前置；唯一性校验（同本体 + 同属性实体 + value_text）由 06 期服务层实现，42 行值域为其提供 datatype 标注。

### 2.7 推理影响声明

与 01/02 期同款：V1 无推理机、不做一致性检查（本仓校验器只做结构 + 词法校验）。函数性、值域 datatype、不相交数据属性等公理为未来推理储备；语义矛盾（如"函数性 + 同体多值断言"）不拦截，矛盾在推理期暴露。展示层级为 Asserted 层级。

### 3.2 内建 XSD 白名单（Go `BuiltinDatatypes` + 前端标签常量）

**Go 侧**（`internal/ontology/types.go` 增量；词法校验分派键为 Kind）：

```go
// 内建 XSD datatype 白名单（15 项，覆盖 06 期编码/名称/数量/日期场景；源注释写"14"系笔误，以其枚举实列 15 项为准）；
// 05 期接管扩展（全量内建 + facet + 自定义 datatype 实体管理），见 §2.2/§10。
type BuiltinDatatype struct {
    IRI  string
    Kind DatatypeKind // 词法校验分派：KindString/KindBoolean/KindDecimal/KindInteger/.../KindDate/KindDateTime/KindTime/KindAnyURI
}

var BuiltinDatatypes = []BuiltinDatatype{
    {IRI: "http://www.w3.org/2001/XMLSchema#string", Kind: KindString},
    {IRI: "http://www.w3.org/2001/XMLSchema#boolean", Kind: KindBoolean},
    {IRI: "http://www.w3.org/2001/XMLSchema#decimal", Kind: KindDecimal},
    {IRI: "http://www.w3.org/2001/XMLSchema#integer", Kind: KindInteger},
    {IRI: "http://www.w3.org/2001/XMLSchema#long", Kind: KindInteger},
    {IRI: "http://www.w3.org/2001/XMLSchema#int", Kind: KindInteger},
    {IRI: "http://www.w3.org/2001/XMLSchema#short", Kind: KindInteger},
    {IRI: "http://www.w3.org/2001/XMLSchema#byte", Kind: KindInteger},
    {IRI: "http://www.w3.org/2001/XMLSchema#nonNegativeInteger", Kind: KindNonNegInteger},
    {IRI: "http://www.w3.org/2001/XMLSchema#float", Kind: KindFloat},
    {IRI: "http://www.w3.org/2001/XMLSchema#double", Kind: KindFloat},
    {IRI: "http://www.w3.org/2001/XMLSchema#date", Kind: KindDate},
```

### 4.2 创建 / 更新事务管线（create / update 共用，frame 全量提交）

```
1. 本体存在且启用
2. localName 合法（create）；update 忽略 local_name（01 号文档语义）
3. IRI 查重（create，双层）                                     → ENTITY_IRI_DUPLICATE
4. 引用目标类型与存在性校验（ValidateRefEntities）：
     superPropertyIds / disjointIds / equivalentId → DATA_PROPERTY → DATA_PROPERTY_TARGET_INVALID
     domainIds                                     → CLASS       → DATA_PROPERTY_DOMAIN_INVALID
   自引用语义（对齐 01/02 号文档）：
     superPropertyIds 含自身                       → 交由环检测（HIERARCHY_CYCLIC）
     disjointIds / equivalentId 含自身             → DATA_PROPERTY_SELF_REFERENCE_INVALID
   （create 不做自引用校验——新实体尚无 id）
5. 值域校验：range_iris 去空白、有序去重后逐个 IsBuiltinDatatype → DATA_PROPERTY_RANGE_INVALID
6. 特征校验：characteristics ⊆ {owl:FunctionalProperty}          → DATA_PROPERTY_CHARACTERISTIC_INVALID
7. 属性环检测：hierarchy.AssertNoCycle(entityType=DATA_PROPERTY, edge=40)
8. 组装 EntityChangeSet → ChangeApplier.Apply()（乐观锁 → 公理增删 → 注解缓存同步 → 校验器 → version+1 → 日志）
```

**update 差异计算（frame 全量替换，逐 section diff）：**

| section | diff 规则（组件） |
|---|---|
| superPropertyIds | `DiffSubjectSideRelations`（40 型，同 01/02） |
| domainIds | `DiffSubjectSideRelations`（41 型） |
| rangeIris | **`DiffSubjectSideValues`**（42 型按 **value_text 集合** diff，删多余行、按提交序补新行）——与 02 期特征 diff 同构，比对键从 predicate_iri 换成 value_text；**新增行 sort_order 从存量最大值后顺排**（存量行不动：混合编辑后回读序与提交序一致——源修订 #2 内化，值域列有顺序语义故收紧） |
| characteristics | `DiffCharacteristics`（43 型按 predicate_iri 集合；实现为 `DiffCharacteristics(subject, axiomType, current, targetIRIs)` 参数化签名，33/43 共用同一组件、各自传型，不复制组件——V1.1 修订 #3） |

### 4.3 usage 反查与删除保护（对应 `OWLDataPropertyUsageViewComponent` + `OWLEntityDeleter`）

|---|---|---|---|

**delete 语义（与 01/02 期同款）：**

- `force=false`（默认）：存在引用 → `ENTITY_IN_USE`（409）+ 引用清单（引用方式标签：子属性 / 等价 / 不相交；06 期追加"个体断言"）；
- `force=true`：级联删除——① 以 P 为 object_id 的行（40 子属性边、44/45 伙伴镜像行；06 期含 62 断言行）；② 以 P 为主语的全部公理行（40/41/42/43/44/45 主语侧 + 注解 100 + DECLARATION 10）；随后软删实体行。同一事务、同一乐观锁、同一变更日志；

**类 usage 集扩容（01 号文档预埋的 03 期执行点）**：`ClassUsageAxiomTypes` 由 `{20,21,22,31,32}` 扩为 `{20,21,22,31,32,41}`——类删除保护现在能看到"被数据属性定义为定义域"的引用；force 级联同时清理以该类为 object_id 的 41 行；前端类页 usage 弹窗 refTypeName 映射补 `41 定义域` 标签。

### 4.4 AxiomValidator 与渲染器 03 期增量

本仓无 OWLAPI 投影，源 §4.4 投影分支表转译为**结构规则 + 词法校验 + Manchester 渲染**：

**validator.go 增量：**

| 类型 | 校验规则 |
|---|---|
| 40 / 44 / 45 | 两端实体均存在、未删、`entity_type = DATA_PROPERTY(30)` |
| 41 | subject 为数据属性、object 为已声明**类** |
| 42 | value_text ∈ `BuiltinDatatypes` 白名单（服务层已拦，校验器兜底直改库脏数据；05 期双轨后 object_id 优先） |
| 43 | predicate_iri = 函数性常量（≠ 则 `AXIOM_INVALID`） |
| 62 | subject 为已声明个体、object 为已声明数据属性（asIndividual / asDataProperty 语义）；字面量按 §2.6 规则校验：`lang` 有值 → 仅要求 value_text 非空（rdf:langString）；否则 → 取该属性第一条未删 42 行 value_text 推断 datatype（无值域行缺省 `xsd:string`）→ `lexical.go` 词法校验，失败 → `AXIOM_INVALID` 回滚 |

**lexical.go（新增，内建 datatype 词法校验，Go 标准库实现）：**

| Kind | 实现 |
|---|---|
| String | 无词法约束（允许任意 Unicode 文本） |
| Boolean | `true` / `false` / `1` / `0` |
| Decimal | `strconv.ParseFloat` 或 decimal 词法正则（可选符号 + 数字 + 可选小数） |
| Integer（long/int/short/byte） | `strconv.ParseInt`（按宽度的语义差异 V1 不细分，64 位解析通过即可） |
| NonNegInteger | ParseInt 且 ≥ 0 |
| Float / Double | `strconv.ParseFloat` |
| Date | `2006-01-02` 可选时区后缀（`time.Parse` + 正则兜底） |
| DateTime | `time.Parse(time.RFC3339)`（XSD dateTime 要求时区，RFC3339 同构） |
| Time | `HH:MM:SS(.fff)?(Z\|±HH:MM)?` 正则 |
| AnyURI | 非空且无控制字符 |

（源实现曾踩"OWLAPI 不校验词形 + xsd:date/time 不在 OWL 2 DL datatype map"两个坑——本仓自写词法校验，15 类型统一覆盖，坑不存在，但"校验只在校验器做"的纪律与源一致。05 期 facet 扩展在此文件之上叠加。）

**render.go 增量：**

```
SubPropertyOf(P Sup) / Domain(P A) / Range(P xsd:integer)
Characteristic(P, functional) / EquivalentDataProperties(P Q) / DisjointDataProperties(P Q)
DataPropertyAssertion(张三 P "42"^^xsd:integer)    // 62 行渲染（06 期个体 frame 复用）
```

成对行（44/45）渲染按无序对去重展示，与 01/02 期同理。62 分支本期落地（个体实体尚无写入方，分支先行无副作用，06 期零改动可用）。

## 7. 异常与边界场景清单

| # | 场景 | 行为 |
|---|---|---|
| 1 | IRI 重复（同名属性） | `ENTITY_IRI_DUPLICATE`，表单局部名红字；partial unique index 兜底并发 |
| 2 | 环：把子孙属性设为父属性（含自环） | `HIERARCHY_CYCLIC`，环路径文字 |
| 3 | 定义域选中非类实体（如数据属性/对象属性） | `DATA_PROPERTY_DOMAIN_INVALID`，指明实体 |
| 4 | 父属性/等价/不相交目标不是数据属性（或跨本体） | `DATA_PROPERTY_TARGET_INVALID` |
| 5 | 等价/不相交自引用 | `DATA_PROPERTY_SELF_REFERENCE_INVALID` |
| 6 | 值域 IRI 不在白名单（手写请求绕过前端） | `DATA_PROPERTY_RANGE_INVALID`（服务层）+ 校验器双拦 |
